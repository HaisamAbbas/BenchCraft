# G11 — Headless run supervision

**aibench run --detach** creates a normal frozen run, starts a worker with the active Python
interpreter, and returns the run ID and log path. **aibench resume RUN_ID --detach** does the
same for an unfinished run. The worker inherits no interactive input, writes stdout and
stderr to **.aibench/logs/run-<digest>.log**, starts in a new process group/session, and uses
the normal run lease before it can dispatch work. The log filename is derived from a hash of
the run ID, so run identifiers cannot escape the workspace log directory.

**aibench runs control RUN_ID pause|resume|cancel** persists a desired state and an audit event
in one SQLite transaction. Requests receive a per-run sequence number; the worker polls the
latest sequence while starting and while scheduling work, applies unseen requests through
the existing run controller, and records **run_control_applied**. The latest pause/resume
request wins. Cancellation is irreversible and is rejected if a later request attempts to
resume the cancelled run. An offline cancel remains pending; the next **aibench resume
RUN_ID** preserves it and starts a session only to finalize cancellation, without dispatching
new application work. A resume request can release a worker draining after its first Ctrl-C;
once a second interrupt has aborted in-flight work, the durable request remains for the next
session instead of being reported as applied by the exiting worker. Otherwise, root
**aibench resume RUN_ID** resumes an active worker through this control channel, or persists a
resume request before starting a new local session when no worker is live.

**aibench runs status RUN_ID** reports the worker lease (live, stale, or absent), desired
control state and sequence, plus the last detached launch's process ID and log path. It
distinguishes a launching, starting, running, stale, exited, unknown, or failed-to-launch
process and reports whether that process owns the current lease. A later foreground resume
therefore cannot be mislabeled as the earlier detached process. External control is accepted
only for plan-based runs supported by the headless engine.

The end-to-end regression starts a detached worker, pauses it from a separate CLI
invocation, verifies that dispatch stops, resumes it through root **resume**, then cancels it
through **runs control**. It also checks that the durable sequence and final lease state are
reported. A separate regression queues cancellation with no worker and verifies that
**resume** finalizes it without invoking the application.
