# G14: warmup and measurement phases

Plans can set `warmup_repetitions` from 0 to 100 per selected case. `aibench run --warmup-repetitions N` overrides that value for one run, and dry-run/plan validation output separates warmup execution items from measured execution and evaluation items.

The engine runs every planned warmup before dispatching measured work. A warmup remains a durable execution work item, including across interruption and resume, and has no evaluation work item. Warmups bypass execution-cache lookup so the configured warmup calls reach the application. Retries remain in the warmup phase and hold the phase barrier until they settle. Existing application reset behavior still applies to warmup attempts.

Warmup calls consume application-call, cost, quota, and wall-time budgets. Their committed attempts remain in total application call and spend accounting; reports also break out warmup planned/recorded/completed/failed counts, attempts, cost completeness, and final effect states. Warmup failures do not enter metric evidence or automatic failed-measurement retry selection, while their effect risks still inform whether retrying a case is safe.

Metric scoring and case-result export contain measured repetitions only. Application latency percentiles and comparison latency use successful final measured executions only. Comparison compatibility includes the warmup count, and comparison cost continues to include warmup calls with a separate warmup dispatch/cost summary.
