# F04 — Freeze application and runtime identity for resume

Status: DELIVERED. The implementation and review evidence are recorded in the audit
implementation ledger; the delivery commit is pushed to `origin/fix/plugin-core-match`.

Resume now refuses pending work if local application source, inherited environment, runtime,
or imported Python code differs from the identity frozen when the run was created. Python
identity covers the executable bytes and runtime, ordered import roots, standard-library
files, site/user-site packages, editable installs, and static path entries in `.pth` files.
Executable or unreadable `.pth` files, secret or redirected Python paths, and inventories
that exceed safety bounds require an owner-supplied `environment_digest` before a run can be
resumed. Remote applications require a declared revision or environment digest. `runs show`
reports the identity basis and any resume requirement.

The discovery probe runs with site startup disabled and parses `.pth` files as data, so it
does not execute package startup code during identity checks. Resume checks happen before
dispatch when work is pending; scoring-only completion and terminal cancellation can still
settle without launching changed application code. The change also preserves the virtual
environment executable path so its `pyvenv.cfg` and effective site roots can be identified.
