## Worker setup follow-up

A follow-up review found two setup defects. First, the generated remote command invoked bare
`python`, although the documented fresh-checkout setup uses the project's `uv` environment. On
a worker without a globally installed BenchCraft package, that could select a Python interpreter
unable to import `aibench`. Second, the generated command hardcoded `worker-app.json` even when
`--worker-app-config-out` wrote a differently named file. The printed fixture and worker
commands now use `uv run --locked`; the worker command uses the generated file's basename, and
the operator instructions direct both commands to run from the matching checkout root with the
config copied there under that name. A regression uses a space-containing filename to verify
shell quoting. The guide also records a small recommended VM profile and the network
requirements; these are setup guidance, not a capacity claim.

The read-only follow-up review found no remaining actionable issue in the changed command,
quoting, or checkout-relative config flow. Verification passed: the focused distributed suite
(**27 passed**), `uv run --locked python -m aibench worker connect --help`, Ruff check and
formatting, and `git diff --check`. These checks still use the local host and do not establish
cross-host performance or failure rates.
