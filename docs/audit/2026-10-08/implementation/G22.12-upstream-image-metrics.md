# G22.12: DeepEval's upstream image metric family

The isolated DeepEval plugin now exposes five metrics from the pinned 4.2.5 image-metric
family: `image_coherence`, `image_helpfulness`, `image_reference`, `text_to_image`, and
`image_editing`. Each uses DeepEval's metric implementation and score/reasoning contract with
an explicitly configured OpenAI-compatible vision judge.

## Evidence and judge contract

The first four metrics take text prompt input. `image_editing` takes a prompt and one inline
source image. All five require one recorded generated image, optionally with a text caption.
Images use the existing strict inline PNG/JPEG/WebP signature checks; URLs, local paths, extra
fields, text-supplied DeepEval image markers, and unsupported MIME types are refused before
the judge call. Source plus output images have a 4 MiB decoded aggregate cap. A case supports
one output image, keeping upstream per-image judge calls bounded. Signature and byte checks do
not validate full image structure or decoded pixel dimensions; corrupt signature-matching data
can still fail after a judge request.

The upstream package requires a model that advertises multimodal support. The new
OpenAI-compatible judge advertises that capability and resolves strict lowercase 32-hex image
markers directly through DeepEval's inline-image registry before constructing Chat Completions
`image_url` parts. It rejects malformed or unknown markers before calling DeepEval's general
parser, along with missing data, remote placeholders, PDFs, invalid base64, MIME/signature
mismatches, more than two images in one judge request, and requests with no registered image.
It never fetches a path or URL. Image registry entries are removed after each evaluation. Judge
replies are capped at 1 MiB. Judge calls, token usage, and reported price follow the existing
plugin usage contract. A failed HTTP response, oversized reply, timed-out transport, or sibling
request cancelled after its bounded settle window marks calls/cost unknown rather than reporting
zero; completed sibling usage is settled before the failed outcome is returned. Token completeness
is tracked per provider request and carried through the worker protocol, stored usage event, and
report resources, so a retry without token usage cannot make a later successful retry appear to
quantify every call. No live provider call was made.

The upstream coherence/helpfulness/reference metrics accept `max_context_size` from 1 to
20,000 characters (default 4,000). Text-to-image and image-editing preserve DeepEval's two
sub-score arrays and report them in stored raw metric details. The harness applies its frozen
decision rule to the normalized 0-to-1 result.

## Verification

- Five metric manifests were discovered from the real plugin environment, including package
  identity, worker isolation, required fields, model use, image bounds, and retry declaration.
- The real pinned package accepted the custom judge as multimodal and sent generated PNG bytes
  to a local Chat Completions fixture through every upstream metric.
- Decoder tests rejected remote URLs, malformed signatures, filesystem paths, text-only
  outputs, and reserved image markers without a judge request.
- The final combined image-metric, worker-usage, and report regression batch passed 25 tests.
  Coverage includes unknown path/URL marker rejection before DeepEval's parser, missing
  image-editing source rejection, delayed parallel-judge usage settlement, cancellation and
  retry accounting, oversized-response refusal, malformed/negative/non-finite/overflowing
  provider usage, and token-completeness propagation through a real worker to stored events and
  report resources. The independent reviewer's final three-test regression batch also passed.
- Ruff checks passed; formatting passed for the 11 selected changed files checked. Mypy found no
  issues in the seven affected source modules. `git diff --check` passed. No paid or external
  model request was made.
