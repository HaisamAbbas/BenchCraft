# F07 — Preserve planned selections during rescoring

Status: DELIVERED. Commit `8050013e71befb67c26c6076c13ccfe0ad395efb` is pushed
and verified on `origin/fix/plugin-core-match`.

Rescoring now summarizes every execution item selected by the original frozen work
graph. Items with no recorded application output remain in the denominator as
unavailable (`not_executed`), so they lower coverage instead of disappearing. Runs
without a work graph keep the legacy basis of final recorded executions. A scoring pass
freezes its selected count in the pass event; the report builder uses that same count.

The rule also applies to new metric bindings and runs with zero recorded executions but
selected work. CLI evaluation, session `/rescore`, and stored reports therefore show the
same selected/completed/unavailable counts. The app remains untouched during rescoring.

Validation: **13 selection cases** and **43 adjacent regressions passed**. Tests include
pending, cancelled and blocked work, no output, partially recorded output, repetitions,
colon-bearing case IDs, stale workspace catalog entries, changed metric settings,
session rescoring and report/CLI equality. Full Mypy (140 files) and Ruff passed.

Independent review first found that remote-job passes without the recorded-output rescore
event must keep using their uploaded result set. The report branch now applies the frozen
selected count only to actual rescore passes or runs with an engine work graph; the added
remote-style test verifies that the pass's one uploaded result remains selected=1.
Final review: **No findings.**
