# G22.8: generated-image vision evaluation

`deepeval.vision_g_eval@1.1.0` accepts either a bounded text answer or a recorded inline
image output. This extends the image-first G22.5 evaluator so a vision judge can assess the
application's generated image beside the case image, task prompt, and reviewed reference.

## Output contract

An image output is exactly this JSON object at the application's selected output path:

```json
{"mime_type":"image/png","data_base64":"<base64 image bytes>"}
```

PNG, JPEG, and WebP are supported. The adapter strictly decodes base64, checks the MIME type
against the image signature, and limits each case or generated image to 4 MiB decoded. It
rejects URL/path outputs, other shapes, unsupported types, malformed data, mismatched
signatures, and oversized images as not applicable before a judge request. Text outputs retain
the existing bounded-string contract.

For an HTTP application, the JSON/base64 response is larger than the decoded image. Raise the
application transport's `max_response_bytes` when needed so the runner does not truncate the
response before it records the selected object. The configured evaluator policy and plugin
environment requirements are unchanged. Both images, task, reference, and output are sent to
the configured OpenAI-compatible vision judge as labeled text and inline data URLs. The
adapter does not fetch output URLs, read local files, follow redirects, or persist image bytes
in its sanitized score artifact.
