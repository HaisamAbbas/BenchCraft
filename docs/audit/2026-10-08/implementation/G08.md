# G08 — Reproducibility controls and provenance

`aibench run --run-seed N` now sets the engine seed independently from case-selection
seeding. The CLI validates the engine's supported range, includes the requested seed (or
explains that creation will choose one randomly) in dry-run output, and reports the actual
seed in run completion output. `aibench runs show` exposes the seed and frozen provenance in
JSON and human-readable output.

Run manifests record the local application's source and environment identity, available
dependency/plugin/model identifiers, BenchCraft version, and host runtime. For local Python
and CLI applications in Git worktrees, they also freeze the commit, tracked working-tree diff
hash, and a content hash/count for non-ignored untracked files beneath the application root.
Resume compares those values before recovery or dispatch and refuses source, environment, or
worktree drift. Git fingerprints are bounded: tracked diffs are capped at 64 MiB, the
untracked path list at 8 MiB/2,000 files, and untracked file contents at 64 MiB total. Scanner
errors, symlinks, and filesystem reparse points fail closed unless the application declares
an owner-supplied revision or environment digest. Ignored files and external resources remain
the responsibility of that owner declaration.

Validation: the full affected run/CLI/recovery batch passed 55 tests. After the final
reparse-point and human-output changes, 6 focused Git provenance regressions and all 12
`runs show` tests passed. Ruff passed for `src tests plugins`; Mypy passed for 149 source files;
`git diff --check` passed.

The independent review first found that changed untracked prompt/config files could escape the
resume identity, then found that Windows junctions could expose files outside the application
root. The implementation now fingerprints bounded non-ignored untracked files and rejects
reparse points on every path component. The final reviewer pass reported no findings; evidence
is in [`G08-review.md`](../evidence/G08-review.md).
