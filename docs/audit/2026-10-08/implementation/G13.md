# G13 — Structured progress and durable logs

Run commands now expose durable run events to scripts and operators. `run`, `resume`,
and `runs retry` accept `--log-file PATH` to append versioned JSONL records, `--verbose`
to write event records to stderr as they occur, and `--quiet` to suppress human progress
and completion text. The root `--quiet` and `--verbose` options also apply to supported
subcommands. Quiet and verbose cannot be combined; JSON output remains available in quiet
mode.

`aibench runs events RUN_ID` reads the committed event history. `--after N` starts after a
sequence cursor, `--follow` polls while work is live or resumable, and `--jsonl` writes one
machine-readable event per stdout line. Each object uses schema `aibench.run-event/1` and
contains `run_id`, `sequence`, `event_type`, `created_at`, and `payload`. `--verbose` adds
payloads to human-readable event lines. `--log-file PATH` appends the same JSONL records;
quiet mode leaves stdout empty while continuing to write the selected file.

Event-log files are append-only. Existing records must be valid BenchCraft run-event JSONL,
end with a newline, and remain in increasing sequence order for each run. A sibling `.lock`
file coordinates writers across processes. A run reserves its destination before creating a
run or persisting a resume request, then transfers that reservation to its event stream. A
detached worker waits for the launcher to hand off the reservation before dispatch. Use
`runs events RUN_ID --follow` to watch a worker that already owns an event-log destination;
the follower can write a different file, or stream JSONL to stdout.

Invalid destinations fail before the run or resume control change. If a write fails after
execution begins, the logger warns on stderr and the benchmark continues; durable events
remain available from the workspace database. These commands do not prompt for input, so
they remain suitable for noninteractive scripts.

Focused regression coverage checks schema and cursor output, quiet JSON behavior, append and
follow behavior, invalid destinations, active-writer rejection and lock handoff, oversized
cursors, and detached-worker event ordering. Independent review and verification are recorded
in [G13-review.md](../evidence/G13-review.md) and
[G13-verification.txt](../evidence/G13-verification.txt).
