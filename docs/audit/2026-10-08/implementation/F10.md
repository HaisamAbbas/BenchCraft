# F10 — Normalize malformed CLI input errors

Status: DELIVERED. Expected malformed-input failures now remain inside the CLI's domain
error handling and produce stable JSON error envelopes when `--json` is selected.

The CLI shares one error document shape across dataset, trace import, run, plan, and
headless slash-command failures. Invalid UTF-8 config and dataset files become domain
validation errors; malformed YAML diagnostics report a location without echoing file
contents. Plan validation and planner policy denials retain their actionable detail in JSON.
The model planner's benchmark path also handles malformed policy files without leaking an
uncaught exception.

OTLP parsing validates nested containers, AnyValue arrays/key-value maps, and string keys
before conversion. Malformed nested input raises `TraceFormatError`; it cannot become an
uncaught `TypeError` or be silently accepted after falsey values are defaulted.
Malformed slash-command quoting becomes a user-facing validation error, and Typer's
exception renderer does not show local variables.

Validation and independent review are recorded in [verification](../evidence/F10-verification.txt)
and [review](../evidence/F10-review.md).
