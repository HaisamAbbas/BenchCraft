# G22.4 — Open-loop and ramping load profiles

BenchCraft now supports closed-loop (default), fixed-rate open-loop, and ramp-up-to-target
load profiles. Plans freeze the profile in their canonical plan artifact and hash. Direct
`run` controls can select `--open-loop-rps N`, or the complete set
`--ramp-start-rps N --ramp-end-rps N --ramp-duration-seconds S`; `--closed-loop` restores the
default behavior for one invocation. Dry-run shows the effective profile.

The coordinator schedules only fresh, measured first attempts. Warmups settle before the
profile clock begins; retry attempts follow the existing retry policy and consume no arrival
slots. Fixed-rate targets use `ordinal / rate`, with the first arrival at offset zero. Ramp
targets invert the cumulative linear rate from the starting rate to the final rate, then hold
that final rate after the ramp duration. Application concurrency, quotas, budgets, and the
existing 500-item queue bound remain in force. Execution caching is rejected for open-loop
and ramp profiles.

The profile clock freezes during a user pause. A resumed engine session gives the remaining
unstarted first attempts a fresh schedule beginning at offset zero. Each observed arrival
event is recorded immediately before the request is handed to its runner, after any required
application reset. Reports include the frozen profile, planned and observed measured
first-attempt dispatch counts, and nearest-rank dispatch-lag statistics. Lag includes reset
time and scheduler/runner hand-off delay; it excludes remote worker queueing, network delay,
and application-observed request start, so it is not end-to-end latency.

Validation:

- The focused profile, plan, CLI, engine recovery/concurrency, and report batch passed: 28
  tests.
- Windows-target Mypy passed for all 173 source files; Ruff passed for `src` and `tests`;
  `git diff --check` passed.
- An earlier combined 76-test batch reported 72 passes and four failures while source files
  were being edited concurrently. Three failures were the harness detecting those live
  worktree changes in frozen application Git identities. The fourth exposed a legacy report
  with no frozen plan profile; rendering now skips that optional row, and all four exact
  failures passed in the stable 28-test rerun.

The scheduler's dispatch-lag measurement has been validated with local subprocess runners.
No remote-worker throughput, worker-side queue latency, TLS deployment, or application-side
arrival timestamp is claimed. These remain separate distributed performance measurements.
