# G22.9 independent review

The requested read-only review-agent examined the evaluator, plugin identity, worker integration,
payload handling, judge request/accounting, tests, and documentation.

It first found three actionable issues:

- WAV metadata checked for nonzero values but did not enforce format, rate, block alignment, or
  data-chunk consistency. The evaluator now supports PCM/IEEE-float WAV only and validates RIFF
  bounds, sample rate, byte rate, sample width, block alignment, and each data chunk. Regressions
  reject a fake RIFF prefix, a zero byte rate, and an inconsistent block alignment.
- The documented 4 MiB evaluator cap exceeded standard JSONL and HTTP transport caps. The plugin
  guide now records the 1,000,000-byte JSONL line limit, the default 1 MiB HTTP limits, the
  approximate case-audio limit after base64 overhead, and an 8 MiB response-limit example.
- The report/backlog linked to a missing implementation note and the ledger described only
  G22.1-G22.8. The implementation note and this review record are now present, and the ledger
  records G22.9 as delivered with feature commit `bf9a6f10528f1088fd1d19f2a9683e7928419484`, pushed to `origin/fix/plugin-core-match` and confirmed at the remote ref.

The reviewer confirmed that the documented `input_audio` request shape, MP3 frame validation,
judge endpoint controls, size bounds, token accounting, and sanitized artifact behavior are
appropriate. After these fixes it reported no remaining functional or security findings; the
only prior residual finding was the closeout documentation gap, now resolved.
