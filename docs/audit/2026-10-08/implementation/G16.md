# G16: streaming model performance

OpenAI-compatible application configurations can set `transport.parameters.stream: true` to benchmark server-sent event responses. The default remains the existing JSON request path, and the opt-in setting does not change the serialized transport schema or existing application hashes.

For streamed calls, BenchCraft reconstructs the chat-completion response from content, tool-call, finish-reason, and usage deltas, then sends it through the existing output extraction and redaction path. By default the request asks for `stream_options.include_usage`; providers that reject usage chunks can disable that option, which leaves output tokens/sec unavailable.

Each execution records TTFT from request start to the first non-empty content delta; inter-content-delta intervals based on receive times for accepted response chunks; reported output tokens and usage-based tokens/sec; and stream integrity. Integrity requires the `[DONE]` marker, the requested choice indexes and finish reasons, and well-formed events. Content after a choice finish or the stream terminator makes the response invalid. Partial timings remain attached to an incomplete execution for diagnosis.

Inter-delta timing is a transport observation: providers can combine tokenizer tokens in a delta, and network buffering can coalesce events. Up to 100,000 intervals per response are retained, with truncation reported. Tokens/sec uses the provider's `completion_tokens` from a complete usage-bearing stream divided by time from first content through `[DONE]`; it does not infer tokenization locally.

Measured and warmup summaries are available in JSON reports and comparisons, with TTFT, inter-token gaps, token-rate percentiles, output-token totals, and integrity counts. Markdown/HTML reports and the comparison TUI show the corresponding human-readable statistics. The local OpenAI-compatible fixture emits flushed SSE events and can exercise incomplete streams without paid calls.
