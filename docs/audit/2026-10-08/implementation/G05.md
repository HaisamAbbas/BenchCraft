# G05 — CI report adapters

Extended `aibench report --format` with JUnit XML and SARIF 2.1.0. Both are generated from
the same stored report and selected case/repetition facts as the human-readable formats;
they do not invoke applications or evaluators. They share report `--no-content` behavior and
write to the same run-specific report directory, with `.xml` and `.sarif` extensions.

JUnit maps application executions, each metric result, release gates, and overall run
completion to individual test cases. Failed metric decisions and gates become failures;
unavailable execution/evaluation and undecided gates become errors; not-applicable results
and metrics without a decision rule are skips. SARIF emits findings for failed metric
decisions, failing/undecided release gates, application errors, and incomplete runs. It keeps
case/repetition and metric/gate identities in result properties and does not fabricate source
locations for benchmark data. Passing checks do not create SARIF results. Existing
JSON/Markdown/HTML formats and interactive report format selection remain unchanged.

See [CI report adapters](../../../ci-reports.md). SARIF was validated against the official
[OASIS SARIF 2.1.0 Errata 01 schema](https://docs.oasis-open.org/sarif/sarif/v2.1.0/errata01/os/schemas/sarif-schema-2.1.0.json)
for both content modes.
