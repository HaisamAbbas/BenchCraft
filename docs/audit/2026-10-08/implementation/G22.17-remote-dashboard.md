# G22.17: Authenticated remote dashboard

`aibench dashboard` still binds to `127.0.0.1` over HTTP by default. Remote binding is an
explicit opt-in and fails before opening a socket unless the operator provides all of:

```powershell
$env:BENCHCRAFT_DASHBOARD_TOKEN = (python -c "import secrets; print(secrets.token_urlsafe(32))")
benchcraft dashboard --bind 0.0.0.0 --port 8765 `
  --token-env BENCHCRAFT_DASHBOARD_TOKEN `
  --tls-cert .\dashboard-cert.pem --tls-key .\dashboard-key.pem --no-open
```

The token value comes only from the named environment variable. It must contain 32 to 256
URL-safe characters and is never accepted on the command line, placed in a URL, or written to
request logs. Generate it with a cryptographically secure random source as shown above; the
CLI checks its length and alphabet, not its randomness. Remote mode uses Python's server TLS
context with TLS 1.2 as its minimum and
requires a certificate and private key. The `ssl` module documents the server context and
certificate-loading interface; bearer tokens are compared with `hmac.compare_digest`, which
Python documents as avoiding content-based short-circuit timing behavior. See the [TLS
context documentation](https://docs.python.org/3.11/library/ssl.html#ssl.SSLContext) and
[`compare_digest` documentation](https://docs.python.org/3.11/library/hmac.html#hmac.compare_digest).

Every `/api/` GET requires the bearer token. The root page is static and contains no stored
workspace data. In remote mode it presents a masked password field, sends the token only in
the `Authorization` header, and holds it in page memory for that tab. API reads still enforce
same-origin checks, content withholding, query-only SQLite access, bounded request concurrency,
timeouts, request-size limits, and read-only methods. Remote options are rejected on loopback
addresses; a non-loopback address or hostname without all three security settings is refused.
