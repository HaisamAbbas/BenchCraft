# G22.6 — Independent review record

## Findings and resolutions

The first read-only review found three issues. Report and comparison requests had no input
ceiling and the threaded server had no active-request limit (P2); PATCH returned `501`
instead of the documented read-only `405` (P3); and unknown API routes returned `400`
instead of `404` (P3). The server now limits concurrent requests to four, bounds report
and comparison input, explicitly rejects PATCH, and returns `404` for unknown routes.

The second review found three more issues. Legacy runs could exceed the work-item limit
through stored attempts/results or dataset cases (P2); incomplete request lines could hold
all concurrency slots indefinitely (P3); and generic server errors were not logged (P3).
The storage guard now caps indexed scans at 5,001 rows per source table across work items,
execution/evaluation attempts, metric results, run events, trace observations and dataset
cases. Accepted sockets have a 10-second timeout. Unexpected errors return a generic `500`
and log only the exception type. The busy path consumes bounded request headers before
sending `503`, including a Windows regression test for the response.

A later review found that imported trace observations also needed to be included because
report generation materializes them even for runs without a work graph. The capped scan now
includes `trace_observations`, and the legacy-run integration test covers trace-only and
metric-result-only records.

The next review found a snapshot race: separate autocommit reads could observe a concurrent
write between the row-count preflight and report materialization. `_read_storage` now begins a
read transaction before invoking its callback and commits after the complete query. A
regression test commits a trace after preflight, verifies the in-flight report sees the
original empty snapshot, and then verifies the committed trace is visible to a later reader.

The final review then found two remaining HTTP resource edges. The accepted-socket inactivity
timeout alone allowed a slow-drip client to retain a slot, so requests now also have a
30-second absolute deadline that shuts down the socket. Rejected write methods now flush the
`405` first and then drain at most 256 KiB of content-length or chunked data with a short
deadline. Regression tests cover a slow-drip request, a 128 KiB body and a chunked body.

Another review found a busy-path variant of the body issue and a percent-encoding bug. The
overloaded server now reads bounded headers, flushes `503`, and drains no more than 256 KiB of
request-body bytes under a short absolute deadline; regression coverage exercises 512 KiB
content-length and chunked uploads while saturated. Report routes now URL-decode each bounded
path segment, then validate the decoded ID against the run-ID grammar; an encoded-colon report
test covers the UI's `encodeURIComponent` behavior. The reviewer requested a final pass after
these changes; disposition remains pending.

The next review found that the UI parses every error body as JSON while the overload path
returned plain text. Saturated requests now receive a bounded JSON `503` body with `no-store`
and `nosniff` headers; integration assertions verify both the HTTP response and browser-facing
error shape. The final independent review found no remaining issues in the overload path,
percent-encoded run-ID routing, request deadlines or write-body handling.

## Review scope

The review covers CLI registration and shutdown, loopback binding, Host/Origin validation,
response headers and content policy, query validation, path handling, read-only storage
lifetime, records exposed from runs and sessions, report/comparison service reuse, UI
rendering sinks, resource limits and HTTP error behavior.

## Verification boundary

Remote requests remain unsupported, mutation methods are rejected, report content is
withheld, and the API does not run an application or evaluator. Browser automation,
remote authentication and concurrent large-query latency were not measured. The dashboard
is local-only and adds no hosting dependency.
