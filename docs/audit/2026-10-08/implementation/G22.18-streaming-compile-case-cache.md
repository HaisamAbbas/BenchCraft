# G22.18: Stream plan selection and bound run case bodies

Plan analysis now validates and normalizes JSONL rows as a stream. Explicit IDs, predicates,
limits, and deterministic samples are applied as each validated case arrives; unselected case
bodies are released instead of being kept in an ingestion list and a second selection map.
Seeded sampling keeps a max-heap sized to the requested sample and retains the prior SHA-256
rank and dataset-order result. Episode-reset validation keeps case identities by episode.

Compilation no longer materializes every execution and evaluation work item to check the
plan's implicit DAG. That graph is structurally acyclic; analysis checks the generated metric
key suffixes for collisions in space proportional to the number of bindings.

On run start and resume, the engine now retains selected case IDs and reads each frozen Golden
from SQLite through an LRU cache capped at 512 cases and 4 MiB of serialized JSON. The size
budget counts stored UTF-8 JSON bytes; it is not a process-RSS limit. Existing duplicate-ID
and dataset-order behavior is preserved.

## Verification

- Plan validation, planning regressions, ingestion, bounded case-cache, real run/rescore, and
  storage-backed restart selections: 60 passed.
- The opt-in 1,000-case HTTP workload interrupted and resumed successfully with all 1,000
  executions and evaluations succeeded. It measured 13.2 MiB peak traced Python allocations
  over 90.6 seconds. The audit's earlier run measured 17.1 MiB over 64.6 seconds; these are
  single-host traced-allocation samples, not RSS or production-capacity evidence.
- Ruff check and formatting, Windows-targeted Mypy for all five changed source modules, and
  `git diff --check` passed.

The memory result is lower than the earlier sample, with higher observed elapsed time. A plan
that selects every case still keeps the selected immutable case snapshot in `PlanAnalysis` and
`CompiledRun` while `create_run` persists it; streaming bounds ingestion's additional retained
cases and sampled selection, but does not make an all-selected snapshot independent of dataset
size. Cross-host execution and provider behavior were not exercised.
