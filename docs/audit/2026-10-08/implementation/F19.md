# F19 — Preserve selected-work comparison coverage

Status: VERIFIED; commit and push pending.

Comparison uses the engine's work-key parser, including colon-containing case IDs and
repetition suffixes. Short hexadecimal binding keys now match the full `sha256:` binding
identity. If a new rescore binding has no corresponding evaluation work, its denominator
uses the run's planned execution work, including missing outputs. Other cataloged dataset
cases no longer inflate modern run selection.

Changed product file: `src/aibench/services/comparison.py`.
Regression tests: `tests/test_comparison_selection.py`.

Validation: **86 affected tests passed**; full Ruff and Mypy passed. Real CLI tests cover
reused workspaces with limits, seeded samples, explicit case IDs, predicates, repetitions,
partial execution, changed rescore bindings, and zero additional application calls during
comparison. Complete selections show 100% coverage; one missing of two selected cases
shows 50%.

Independent review: **No findings.** Read-only checks confirmed no process dispatch or
plugin imports. Historical records with no parseable work graph retain their documented
catalog fallback; this fix does not invent unavailable historical selection facts.
