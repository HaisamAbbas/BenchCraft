# F15 — Enforce response and trace-file caps while reading

Status: IMPLEMENTED; reviewed, push pending.

Langfuse requests now use HTTPX streaming and stop on the first decoded response chunk past
the existing 20 MiB limit, for both successful and error responses. The OpenAI-compatible
provider applies its 2,000,000-byte limit to successful and error responses in both buffered
and streamed modes. A bounded zlib decoder enforces gzip/deflate output limits during
decompression, so a compressed expansion cannot allocate an unbounded decoded chunk.
Both HTTP clients advertise only `gzip, deflate`, the bounded codecs supported by this reader;
they no longer negotiate optional Brotli/Zstandard encodings that cannot be safely capped here.

Successful SSE parsing remains incremental, recognizes LF, CRLF, and bare-CR separators, and
preserves prompt text delivery. Oversized 429/5xx responses still follow the provider's retry
and `Retry-After` policy without reading beyond the cap.

OTLP trace import checks file size against the artifact store's configured maximum before
opening the file, then reads at most one byte over that cap to protect against a file growing
after the preflight check. Parsing and artifact creation begin only after the bounded read
succeeds.

Validation and independent review are recorded in [verification](../evidence/F15-verification.txt)
and [review](../evidence/F15-review.md).
