# G22.2 independent review

The independent review exercised retry, interrupt, quota fairness, boundedness, and Windows
restore staging paths. It found the following issues during implementation; each was corrected
and covered by regression tests:

- A graceful interrupt cleared the queue and then refilled it from SQLite. The loop now leaves
  undispatched work pending for resume and returns without refilling.
- A full prefetched page could block due retries while dispatch was capped by delayed and
  in-flight work. Due retries can join a separate bounded retry buffer.
- Evaluator retries could be rediscovered from SQLite before their backoff elapsed. Their IDs
  remain reserved while delayed.
- Quota-held and capacity-held evaluations could lose their reservation while temporarily
  outside the deque. Both paths retain their task IDs.
- A shared 500-ID reservation cap could starve an unrelated evaluator behind delayed retries and
  held work. SQL pages remain capped at 500, while the combined bounded reservation buffer allows
  up to 1,000 queue, held, delayed, and running items.
- In-flight evaluations were initially excluded from reservation accounting, allowing retry
  completions to overflow the buffer. Reservations now remain held until the evaluation becomes
  terminal or leaves scheduling; retry completions reuse their reservation.
- The shortened Windows restore staging prefix bypassed two race-test hooks and cleanup checks.
  Those selectors now cover both Windows and POSIX staging names.

The final independent review found no remaining code findings. Large-workload end-to-end memory
and throughput were not measured; case compilation and the case map still retain input cases.
