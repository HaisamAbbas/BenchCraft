# G22.16: Deterministic WER and CER

`deepeval.word_error_rate` and `deepeval.character_error_rate` compare one case's reference
transcript with the `provider_transcript` recorded in that application's output. These metrics are
case-local, so earlier turns in a grouped call are never counted again in later case results. They
run in the isolated plugin worker without DeepEval models, network calls, or audio decoding.

Each metric uses a minimum-edit dynamic-programming alignment and returns
`(substitutions + deletions + insertions) / reference_units`. WER units are whitespace-delimited
words. CER units are Unicode code points, including whitespace that remains after normalization.
The episode/run report's mean is an utterance-level macro-average; raw edit and reference-unit
counts are retained so a corpus-level rate can be recomputed by summing those counts.

Both sides are NFKC-normalized. Case-folding and Unicode punctuation removal are enabled by default
and can be disabled independently with `lowercase` and `strip_punctuation`. Each side is limited to
16,000 characters and each alignment to four million dynamic-programming cells. Missing provider
transcripts, empty references, references made empty by normalization, or over-limit alignments do
not produce a score. An empty hypothesis is scored as deletions; no default pass threshold is
provided because an acceptable error rate depends on task and language. The user must bind an
explicit lower-is-better rule.

The case input may be a transcript string or an object with `transcript`; output must be an object
with `provider_transcript`. Other input/output fields are ignored, so the metrics can be bound with
the stored-voice and diarization evaluators on the same cases. The preceding G22.15 extension also
allows `diarization_reference` and `diarization` fields through the transcription G-Eval evidence
reader, closing the co-binding regression found while adding WER/CER: its strict field allowlist
previously rejected these new annotation fields before this evaluator was added.

This is literal text alignment, not semantic transcript accuracy. The separate
`deepeval.transcription_accuracy_g_eval` judges semantic fidelity and may regard harmless number
formatting or filler-word differences as equivalent. No text-only error rate can determine what was
actually spoken without a reference transcript.

## Verification

- The new plugin-worker tests cover discovery, WER substitutions/deletions/insertions, CER on
  Unicode text, normalization toggles, utterance macro-average semantics, empty hypotheses,
  empty normalized references, invalid parameters, and the alignment-work cap.
- The existing stored-voice end-to-end test now scores voice metrics, diarization, WER, and CER
  together through the HTTP runner, execution store, and isolated evaluator worker.
- The transcript G-Eval test runs with speaker annotation fields present and confirms its transcript
  parser ignores those fields correctly.

  selection: 9 passed, 84 deselected in 13.77 seconds.

## Review

The requested review-agent skill's read-only defect-first process covered the complete evaluator,
normalization and dynamic-programming paths, package registration/version changes, co-binding with
G22.15 and transcription G-Eval, and the bounded integration tests. See the [review record](G22.16-transcript-error-rates-review.md).

The implementation follows the standard reference/hypothesis alignment and edit-count approach
documented by the [NIST SCTK SCLITE scoring tool](https://github.com/usnistgov/SCTK/blob/master/doc/sclite.htm).
