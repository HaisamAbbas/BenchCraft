# F17 — Freeze the application spec for developer smoke runs

Status: IMPLEMENTED; independent review passed; push pending.

Smoke runs no longer try to recommit changed application content under the catalog's
first-seen ID. The catalog remains stable, while each smoke run writes the exact application
spec as a verified content-addressed artifact and records its reference in the run manifest.
Scoring already prefers a declared frozen spec; reports now do the same for smoke runs, so
revision metadata reflects the contract that was executed. Historical runs without an
artifact reference retain their catalog fallback.

The CLI regression smokes two revisions with the same application ID. It checks both
per-run artifacts and report revisions, verifies the catalog keeps its original entry, and
scores each revision against its own output-binding contract.

Validation is recorded in [F17 verification](../evidence/F17-verification.txt); independent
review is recorded in [F17 review](../evidence/F17-review.md).
