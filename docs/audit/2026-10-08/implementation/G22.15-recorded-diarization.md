# G22.15: Recorded speaker attribution and diarization error rate

`deepeval.diarization_error_rate` compares recorded application speaker annotations against
reference annotations over one `group_id` episode. It computes a single optimal one-to-one
speaker-label mapping across the episode, then measures false alarm, missed detection, and
speaker confusion in speaker-milliseconds. DER is their sum divided by reference speaker-time;
lower is better, with a default pass threshold of `0.2`.

Each episode turn must contain a reference object at
`input.diarization_reference.segments`, application data at `output.diarization.segments`, and a
bounded inline 16-bit PCM WAV input. A segment has exactly `start_ms`, `end_ms`, and `speaker_id`;
timestamps are non-boolean integers within that clip, and labels are printable non-empty strings
of at most 64 characters. Empty annotation lists are valid. The whole episode is not applicable
when a turn or annotation is missing or malformed, when the reference contains no scored speech,
or when evidence exceeds a cap.

Default scoring retains overlapping speakers and counts speaker-time in the denominator. The
`skip_overlap` option removes intervals where reference has more than one active speaker. The
optional `collar_ms` removes a total-width interval centered on each point where the reference
active-speaker set changes, including the start and end of annotated speech. Labels are matched by
the maximum-overlap Hungarian assignment, so arbitrary application labels do not affect scores.

The evaluator caps episodes at 50 turns, each input clip at 512 KiB, total decoded input audio at
4 MiB, each side at 128 segments per turn and 512 per episode, and each side at 64 speakers per
episode. It does not submit audio or labels to a model and does not identify speakers from audio;
the application must already have recorded its annotation. It does not establish that an application
speaker label refers to the same real person across separate calls.

The existing voice episode parser now accepts the two annotation fields and ignores them while
constructing DeepEval voice test cases, allowing the local voice metrics and this evaluator to score
the same stored episode. The annotation fields remain separately validated by the DER evaluator.

## Verification

- The plugin worker evaluator tests cover label permutation, an assignment where greedy matching
  is suboptimal, confusion, simultaneous miss/false-alarm regions, overlap retention/exclusion,
  collar masking, empty reference speech, missing/malformed evidence, invalid parameters, and
  per-turn/episode segment, speaker, turn, and total-audio caps.
- The stored-voice integration test sends two grouped calls through the HTTP runner and execution
  store, then confirms the plugin worker computes `DER = 0.5` for a merged speaker label.
- DeepEval package discovery/version checks passed for every affected evaluator family: 9 passed,
  84 deselected.
- Final feature selection `tests/test_deepeval_diarization.py` plus the stored-voice integration
  passed: 5 tests in 17.55 seconds; Ruff, Mypy, formatting, and `git diff --check` passed.
- Tests use generated local PCM WAV and do not contact a live audio endpoint, provider, or judge.
