# G22.19: Upstream audio metric release gate

The reported follow-on asked whether BenchCraft could adopt upstream multimodal audio metrics. A release check on 2026-10-12 found no new audio capability to integrate safely, so this item is deferred until a published package exposes a verifiable API.

The official PyPI project identified DeepEval 4.2.8, uploaded 2026-10-02, as the latest release. I downloaded its wheel and inspected every packaged Python source file. The wheel's SHA-256 matched PyPI metadata (`1bc6ec6ad9f36427e5578a01b4a2aaa357d7ac51bb0cd726af7315304b0339f8`), and none contained `TranscriptionAccuracyMetric`. Its `deepeval.metrics.voice` exports the seven voice metrics already supported by the plugin.

The current [upstream transcription-accuracy docs](https://deepeval.com/docs/metrics-transcription-accuracy) describe text-only comparison between caller `Turn.content` and the agent's `Turn.provider_transcript`; they explicitly say the metric reads no audio. Adopting that API would be an upstream replacement for G22.14's G-Eval implementation, not multimodal audio scoring. The public docs and latest released wheel therefore disagree about availability.

The adapter remains pinned to DeepEval 4.2.5 and verifies the exact installed version because its broader field mappings were tested against that release. I also inspected the pinned 4.2.5 wheel (SHA-256 `1a0a3a586e93187f97c86878fa1adc963a3c4f119523db40cdc28254421afeff`); it likewise contains no `TranscriptionAccuracyMetric`. No pin bump was made based on documentation for an API absent from the latest wheel. G22.9 already supplies bounded audio-task scoring through an audio-capable judge, and G22.11 supports the published audio-quality voice metrics.

## Disposition

G22.19 is deferred pending an official released artifact that includes the documented transcription API or a genuinely audio-input evaluation metric. When such a release is available, verify it in the isolated worker against the existing adapter contracts before changing the strict pin. G22 remains partial for separate-host distributed-worker evidence and approved live-provider calibration; the implementation probe exists, and the user said a remote host will be available later.
