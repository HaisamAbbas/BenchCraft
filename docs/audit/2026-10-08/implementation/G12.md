# G12 — Configuration management

`aibench config show` displays effective project values, the winning source for each
setting, the documented precedence, and a stable hash of the redacted effective config.
It honors global `--config` and `--policy` options. Secret references remain visible as
references; values in secret-like extension fields are redacted, and endpoint display strips
credentials, query strings, and fragments. `--json` produces machine-readable output.

`aibench config validate [PATH]` checks the discovered or explicit JSON/YAML project config
and effective values without contacting a provider. `aibench config set KEY VALUE` parses
JSON scalars (unquoted text is a string), accepts nested keys only under `secrets.*` and
`extensions.*`, validates the complete result before replacing the file atomically, and
accepts only secret references in secret fields. JSON and YAML files are supported.

`aibench config profiles add|list|show|use|remove` manages per-user named
OpenAI-compatible provider profiles. Import validates the provider schema and URL port, and
rejects credentials, query parameters, and fragments, so inline URL credentials cannot be
persisted. API keys must use the currently supported `env:NAME` reference form. Config secret
references reject extra fields and empty names. A selected profile supplies the default
assistant provider for chat and the model planner; chat, guided benchmark, and planning
commands also accept `--provider-profile NAME`. Provider-policy checks still run before
planning egress. Existing first-run `provider` settings continue to load for compatibility,
and explicitly running `setup` selects its newly saved model over a previously selected
profile.

Regression coverage exercises effective source precedence, CLI overrides, redaction,
schema validation and atomic failure, secret-reference enforcement, profile lifecycle,
selection in chat and planning, and refusal to persist inline provider credentials.
Independent review is recorded in [G12-review.md](../evidence/G12-review.md); final checks
are recorded in [G12-verification.txt](../evidence/G12-verification.txt).
