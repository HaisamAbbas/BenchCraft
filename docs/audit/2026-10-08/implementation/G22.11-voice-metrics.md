# G22.11: stored voice-conversation metrics

`aibench-deepeval` now exposes seven deterministic, local DeepEval 4.2.5 metrics for recorded
voice episodes: turn-taking naturalness, agent responsiveness, audio integrity, voice
naturalness, speech intelligibility, voice consistency, and voice reliability. They require
`case.group_id` plus the execution's recorded `episode.turns`; they make no model or provider
call.

## Evidence contract and bounds

Each user case input is an object with `transcript`, inline `audio`, and optional call-relative
`audio_start_ms`. A recorded application output is either a transcript string or an object with
`transcript`, optional inline `audio`, and optional `audio_start_ms`. Audio is restricted to
signature-checked, uncompressed 16-bit PCM WAV, mono or stereo, 8–96 kHz and at most 120 seconds
per clip. User clips are limited to 512 KiB; assistant clips to 1 MiB; total decoded audio in an
episode to 4 MiB. Timestamps are non-boolean integer milliseconds within 24 hours. Turn-taking
is not applicable unless every supplied audio clip has a call-relative timestamp; durations are
derived from the WAV headers.

The host stores episode prefixes with bounded sharing and caps evidence sent to any evaluator
requiring `episode.turns` at 50 cases and 7 MiB of worker-JSON representation. Prefixes outside
those bounds are recorded not-applicable before worker dispatch. The serialized-size calculation
uses the same JSON escaping and separators as the evaluator worker, including Unicode-heavy
transcripts. This protects the worker protocol from unbounded prefix copying and oversized
episode payloads.

`agent_responsiveness` is intentionally a narrow proxy: the adapter's stored format carries one
user and one assistant turn per case, so the upstream detector can identify missing assistant
audio but cannot see reprompts, call-ending reasons, interruptions, or live response latency.
The input contract does not accept `latency_ms` or `interrupted`; neither is claimed as scored
evidence. These metrics do not start calls, capture audio, perform TTS/STT, accept remote audio,
decode MP3 or other WAV encodings, or replace human listening tests.

## Verification

- The voice integration suite passed 3 tests, including HTTPRunner output selection, durable
  execution storage, isolated worker scoring, local-only metric manifests, timestamp-aware
  scoring, and refusal of remote, MP3, malformed, and oversized audio.
- The contract regression verifies that the alternating case format cannot represent reprompt
  events, that missing assistant audio is the responsiveness detector's signal, and that
  ignored latency/interruption fields are rejected. It also verifies the 4 MiB aggregate audio
  refusal.
- The core episode suite passed 11 tests, covering prefix sharing for a 1,000-case episode,
  pre-dispatch turn and serialized-byte limits, and ASCII-escaped Unicode boundary accounting.
- Audio, video, vision, and DeepEval metric discovery tests passed 4 tests after version bumps
  to `aibench 0.1.0rc35` and `aibench-deepeval 0.2.0rc20`.
- Ruff and formatting passed for changed Python files. Mypy passed for all 175 core source files
  and for `voice.py`. `git diff --check` passed.
- The independent review resolved three findings about host-side prefix bounds, responsiveness
  semantics, and exact JSON payload accounting; the final read-only review found no remaining
  actionable findings. No live provider or paid model call was made.

The adapter maps to DeepEval's [voice evaluation contract](https://deepeval.com/docs/evaluation-voice)
and [turn-taking naturalness metric](https://deepeval.com/docs/metrics-turn-taking-naturalness).
