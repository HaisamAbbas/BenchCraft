# G10 — Retry only failed application work

`aibench runs retry RUN_ID` creates a bounded child run from a finished plan-based parent.
By default it selects final application errors only when replaying the case is demonstrably
safe: all final repetitions must have a known non-effectful outcome, and no execution work
item may record an unknown, in-flight, or uncommitted failed attempt. `--case` is the explicit
operator opt-in for selected parent-scoped cases, and previews/output identify prior effect
risk. The maximum case count and child repetition count are bounded.

The command supports JSON and human output, `--dry-run`, an explicit child engine seed, and
parent-scoped case selection. Retrying a resumable parent is refused so `resume` cannot change
the parent work graph while retry selection is being compiled. Child compilation revalidates
the current project/global or explicitly supplied policy as well as the parent's frozen
policy, current application/evaluator definitions, unchanged dataset content, and the
verified frozen test-world seed. Lineage is stored in the child manifest and exposed by run
history and report JSON.

Regression coverage exercises safe/default selection and truncation, explicit cases, dry-run
output, repaired application code, denied current policy, dataset drift, side-effectful and
mixed-repetition safety, missing execution results, parent-scope violations, interrupted
parent refusal, frozen world-seed drift, and lineage in `runs show` and reports.

Final independent review reported no findings; see [`G10-review.md`](../evidence/G10-review.md).
Verification is recorded in [`G10-verification.txt`](../evidence/G10-verification.txt).
