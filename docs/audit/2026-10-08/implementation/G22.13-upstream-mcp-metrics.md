# G22.13 — DeepEval upstream MCP metrics

## Delivery

The isolated DeepEval plugin now exposes `deepeval.mcp_use`,
`deepeval.mcp_task_completion`, and `deepeval.multi_turn_mcp_use`, using DeepEval 4.2.5.
Bindings provide a frozen MCP server/tool/resource/prompt inventory and the adapter scores
successfully recorded MCP tool executions. The adapter never discovers or connects to live MCP
servers.

MCP provenance fails closed. A recorded event counts when its explicit type is one of the
documented MCP tool types; generic untyped events count only when the binding opts into
`tool_events_are_mcp_only: true`. A tool request without a successful recorded execution does
not count. Episode metrics return not-applicable when any turn lacks tool telemetry. Invalid
arguments and over-limit evidence also return not-applicable before a judge request.

The limits are 16 servers and 128 KiB of inventory; 64 tools, resources, and prompts of each
kind per server; 256 recorded events per turn, 512 per case, and 1,024 per episode; and 32
successful calls per turn, 64 per case, and 256 per episode. A call is limited to 16 KiB,
call evidence to 64 KiB per case and 256 KiB per episode, each text field to 16,000 characters,
and total episode evidence to 1 MiB.

Inventory, prompts, arguments, and results are sent to the configured judge service. A local
`python_factory` judge makes no provider request. Stored events do not distinguish MCP resource
reads or prompt retrievals, so only MCP tool calls are scored. Image judge request cancellation
and HTTP request failures now also retain unknown-cost accounting across settlement races.

## Verification

- Final MCP and upstream image-metric regression run: 25 passed in 96.32 seconds.
- The pinned DeepEval worker scored all three MCP metrics against a deterministic local judge;
  worker integration and event-boundary/error paths were exercised without a live provider.
- Two judge-transport regressions verified that a dispatched `WriteError` makes aggregate cost
  unknown while preserving a successful sibling's token usage, and that cancellation during
  `DecodingError` gate teardown records the uncertain call.
- Ruff check and formatting, Mypy for the changed judge and MCP modules, and `git diff --check`
  passed.
- Final defect-first review reported no findings. The audit artifact is
  [G22.13 review](G22.13-upstream-mcp-metrics-review.md).

## Remaining limits

No real MCP server or paid judge provider was contacted. Resource and prompt execution events
remain unsupported until the stored execution schema records their type separately. The report
does not claim judge-model equivalence or validate live MCP behavior.
