# G22.5: image-first vision evaluator

The DeepEval plugin exposes `deepeval.vision_g_eval@1.0.0` as a worker-only, model-backed evaluator for single-turn image questions answered with text. The app-facing case input carries the image and prompt; the evaluator receives those fields, the reviewed reference answer, and the recorded application output. The worker projection prevents unrelated references, fixtures, metadata, and case extensions from being sent to the judge.

## Case and binding contract

```json
{"case_id":"receipt-01","input":{"prompt":"What is the total?","image":{"mime_type":"image/png","data_base64":"<base64 bytes>"}},"reference":{"answer":"$18.42"}}
```

`image` must contain exactly `mime_type` and `data_base64`. Supported MIME types are PNG, JPEG, and WebP. Encoded data is strictly base64-decoded, limited to 4 MiB, and checked against the matching file signature. URLs, file paths, extra image fields, unsupported types, malformed base64, mismatched signatures, and oversized images return not-applicable before any network call. The task comes from `input.prompt` or `input.question`. Prompt, reviewed reference answer, and recorded output are required non-empty strings of at most 20,000 characters.

The binding requires a rubric and an `openai_compatible` judge with a configured endpoint, model name, and key environment-variable name. The key is passed using the existing plugin `secret_env` map; it is never a metric parameter. HTTPS is required for non-loopback endpoints, redirects and ambient proxy variables are disabled, and response bodies are capped at 1 MiB. The endpoint's returned JSON must contain a finite 0-1 score and a non-empty reason of at most 2,000 characters. The harness's frozen decision rule decides pass/fail.

Image bytes, prompt, reference answer, and output leave the workspace for the configured judge endpoint. The metric is model-backed and must be explicitly allowed under evaluator policy. Calls are not retried internally. Reported token counts and one model call are recorded; provider cost is unknown unless reported, and the adapter does not invent a price. The raw artifact retains only the score explanation and model name, not image bytes or the provider response.

This slice supports text outputs only. It does not support audio, video, generated-image outputs, remote image fetching, DeepEval's upstream multimodal metrics, a visual review dashboard, or cross-provider score equivalence.

## Paired provider calibration

Reviewed image cases can be repeated under multiple vision-judge bindings by setting the same
`pair_id` on each provider/model variant in `cases.jsonl`. Every variant must preserve the
same image, task prompt, reference, recorded answer, label, and non-judge evaluator parameters;
only `params.judge` may change. Pair IDs are currently limited to
`deepeval.vision_g_eval`, with at most eight distinct endpoint/model bindings per image. Each
binding still has its own case ID, and each case-by-repeat invocation counts toward
`--max-model-evaluations`. A calibration set may produce at most 512 distinct binding-pair
summaries; larger matrices are rejected before evaluator calls.

Each following JSON object is one line in `cases.jsonl`; repeat the same reviewed sample on
the second line and change only the judge configuration and case ID:

```jsonl
{"id":"receipt-a","pair_id":"receipt-01","category":"receipts","metric":"deepeval.vision_g_eval","params":{"judge":{"kind":"openai_compatible","base_url":"https://vision-a.example/v1","model":"vision-a","api_key_env":"VISION_A_KEY"},"criteria":"Read the receipt total."},"input":{"prompt":"What is the total?","image":{"mime_type":"image/png","data_base64":"<same-inline-image>"}},"reference":"The total is 18.42.","output":"18.42","label":"acceptable"}
{"id":"receipt-b","pair_id":"receipt-01","category":"receipts","metric":"deepeval.vision_g_eval","params":{"judge":{"kind":"openai_compatible","base_url":"https://vision-b.example/v1","model":"vision-b","api_key_env":"VISION_B_KEY"},"criteria":"Read the receipt total."},"input":{"prompt":"What is the total?","image":{"mime_type":"image/png","data_base64":"<same-inline-image>"}},"reference":"The total is 18.42.","output":"18.42","label":"acceptable"}
```

The version 3 calibration report compares paired pass/fail agreement, scalar score means,
signed and absolute score deltas, undecided observations, and bounded disagreement examples.
The plain CLI prints the comparison summary; `--json` or `--out` retains the full report.
Bindings are compared in their sorted report order (`B - A` for score deltas). This output is
descriptive: score differences and decision agreement do not establish that providers are
semantically equivalent or interchangeable. A carefully reviewed, representative held-out set
and actual approved provider measurements are still needed for that conclusion.

Pair records must not include credentials. Each binding refers to its key by environment-variable
name, while live calls remain subject to G20's policy and isolated-worker requirements.
