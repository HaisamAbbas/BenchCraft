# G22.13 — Defect-first review

## Findings

The original review found no findings. A follow-up on 2026-10-13 found and verified this issue:

- **P2 — The synchronous judge could report zero spend after an unclassified transport error.**
  `_OpenAICompatible.generate()` accounted for `_TRANSIENT` errors, but an `httpx.RequestError`
  such as `WriteError` outside that retry set escaped without marking cost unknown. A provider
  may have accepted the request before the transport failed. The sync path now records one
  uncertain call and re-raises without retrying; the established retry set remains unchanged.
  A `MockTransport` regression confirms one dispatch, unknown cost, one uncertain call, and no
  replay.

## Assessment

The change maps the pinned upstream evaluators to bounded, explicitly sourced execution
evidence and a caller-supplied inventory. Typed-event filtering, opt-in handling for untyped
events, unsuccessful-call exclusion, episode telemetry checks, and input limits are covered by
regression tests. The judge accounting changes distinguish queued calls from dispatched
requests, retain response/error uncertainty across async gate teardown, account for ambiguous
synchronous transport failures, and avoid retrying errors outside the established safe-retry set.

Residual limits are documented: no live MCP discovery or provider test was performed, and
resource/prompt execution telemetry is unavailable in the current stored event schema. The
focused MCP and image-metric regression suite and Ruff/Mypy checks passed.
