# F05 — Reject non-finite case data

Status: DELIVERED. Commit `299d74cac6077639f380e84d076ab7838b31b5cc` is on `origin/fix/plugin-core-match`.

JSONL parsing rejects non-standard number constants without aborting the remaining lines.
Case validation rejects non-finite floating-point numbers throughout supplied mappings,
containers, Pydantic model fields, and regular/slotted dataclass fields. Exponent overflow
also fails. The check is scoped to case data: evaluator result conformance/error recording
continues to use its existing contract.

Invalid datasets fail CLI validation and run compilation with exit 2, before dispatch or
workspace creation. Finite case values, literal text, nulls and booleans retain their
canonical storage representation.

Changed product files: `src/aibench/core/models.py`, `src/aibench/datasets/ingest.py`.
Regression tests: `tests/test_dataset_finite_numbers.py`.
User documentation: `docs/support.md`.

Validation: **146 affected tests passed**; full Ruff passed; full Mypy passed for 140 source
files. Tests cover constants, exponent overflow, nested case fields, Python API fixtures
and dataclasses, zero-dispatch CLI refusal, and finite storage round trips.

Independent review: **No findings.** The initial review identified a pre-existing dataclass
gap relevant to this item; it was fixed and independently rechecked before delivery.
The final reviewer verified both regular and slotted dataclasses and unchanged finite
serialization. The validator checks supplied data, not new values generated later by
arbitrary user-defined computed fields/custom serializers; those callbacks remain the
caller's responsibility and are not a JSONL input path.
