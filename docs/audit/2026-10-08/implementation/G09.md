# G09 — Release gates in conversation drafts

Conversation sessions can now add release gates through plan patches. A gate targets a
stable metric identity (evaluator ID plus its occurrence in the draft), so inserting or
reordering metrics does not silently move the gate. If its target metric disappears, draft
construction reports a conflict and asks the user to remove or retarget the gate explicitly.
Gate choices flow into the final planning context and executable plan, and the session
preview shows metric bindings and threshold percentages without rounding away fractional
percentages.

Gate authorization is scoped to the user's wording: each threshold is grounded beside its
own metric, existing thresholds remain unless explicitly removed, and gate deletion or
retargeting must identify the intended gate and direction. Regression coverage includes
overlapping gate IDs, duplicate gates on one metric, threshold-only removal, and remove-all
language in preservation clauses.

Validation: 139 tests passed across the affected authorization, model/schema,
session-controller, conversation, and quickstart modules; the complete authorization module
then passed all 35 tests after the final scope fixes. Ruff passed for `src tests plugins`,
Mypy passed for 170 source files, and `git diff --check` passed. Independent review evidence is
