# G22.6 — Local read-only dashboard

Status: implemented and independently reviewed

## Scope and behavior

`aibench dashboard` starts a small standard-library HTTP server on `127.0.0.1` and opens a
static browser page. `--workspace`, `--port` and `--no-open` control project selection,
local port and browser launch. The page presents the latest 50 stored run and session
summaries, shows content-withheld report facts, and lets the user explicitly compare two
stored runs.

The JSON API has four read-only surfaces: paged run summaries, session summaries, report
facts for one run, and an on-demand comparison of two stored runs. Each request opens a
query-only SQLite connection; report facts and comparisons reuse the same services as the
CLI. No application or evaluator is run. Session summaries omit project/policy paths and
conversation content. Run summaries omit notes and environment values. Reports use
`include_content=False` and `report_facts`, so text answers, references, contexts and raw
artifact contents are withheld.

The server rejects non-local Host/Origin values, sends no CORS permission, sets
`Cache-Control: no-store`, `nosniff`, a restrictive content security policy and
`frame-ancestors 'none'`, and renders database values with text nodes rather than HTML.
Write methods return `405`. At most four requests are processed at once, incomplete request
sockets time out after 10 seconds of inactivity or a 30-second total request deadline, and
saturated servers return `503`. Rejected write methods flush `405` before draining at most
256 KiB of content-length or chunked body data under a short deadline, avoiding unbounded reads
and making the response available to clients. Each report or comparison request reads its
preflight count and materialized facts from one SQLite snapshot. A report route decodes and
validates percent-encoded run IDs, including IDs containing colons. When all request slots are
busy, the server reads bounded headers, flushes `503`, and drains at most 256 KiB of request
body data. The busy response is JSON, matching the browser API helper. Report and compare requests
are rejected with `413` if either selected run has more than 5,000 source rows across work items,
attempts, results, run events, trace observations and dataset cases; this also bounds legacy
runs with no work graph. Each indexed table scan stops at 5,001 rows. Unexpected failures
produce a generic response and a log containing only the exception type. The implementation
adds no runtime dependency and no database migration.

## Limits

This is local-only and has no user authentication. Remote access, reverse-proxy deployment
and shared hosting are unsupported; a future remote mode needs an authenticated deployment
design and a separate review. Browser automation was not run. The 5,000-source-row cap
bounds report/comparison input rows; concurrent large queries were not load-tested. Session
conversations, raw answer text, plugin catalogs,
installation, revocation and MCP exposure are not provided by this item. Cross-host
distributed throughput remains unmeasured under G22.3.
