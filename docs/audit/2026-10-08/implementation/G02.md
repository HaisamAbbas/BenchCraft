# G02 — Stable machine-output API

G02 establishes a versioned result envelope for every CLI `--json` command and a shared
error document for expected failures. Existing object result fields remain at the top level
for compatibility, with `_cli.schema` and `_cli.exit_code` added. Array and scalar results
use a `data` field. The shared console disables Rich highlighting for JSON even when stdout
is a color terminal.

All CLI JSON consoles use the shared formatter. The raw JSON writers used by `benchmark`
and headless chat now use the same envelope. Expected validation, policy, workspace,
connector, and operation errors flow through a shared helper; root `--json` is detected
even where a command also has a local JSON option. Expected error documents carry their
own schema and a process-matching exit code. The entrypoint also preserves JSON mode for a
workspace schema that is newer than the CLI supports.

Commands that need confirmation require `--yes` under `--json` and return a structured
error rather than printing a prompt into stdout. Non-JSON interactive behavior remains
available. JSON Lines progress events, file logging, and verbosity controls remain the
separate G13 deliverable; the one-document result contract keeps progress off stdout.

The envelope semantics and examples are documented in [machine-readable CLI output](../../../cli-machine-output.md).
