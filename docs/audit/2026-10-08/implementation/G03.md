# G03 — Regression policies for CI

`aibench compare BASELINE CURRENT --regression-policy FILE.json` now evaluates
predeclared tolerances against the selected strict comparison. Policies can limit metric
degradation in native units, p95 latency increase in milliseconds, and total observed
application cost increase in USD. JSON and safe YAML inputs are accepted, unknown fields and
invalid thresholds are rejected, and a stable policy hash is included in the result.

Comparison output carries storage-only runtime snapshots. Latency uses final successful
uncached execution attempts and nearest-rank p95; each such request needs a valid timing.
Cost covers all dispatched attempts and is measurable only when every dispatch, including
recovered uncommitted dispatches, has known cost. Metric rules require a unique matching
metric with a qualified comparison and passing per-metric and overall coverage gates.
Point-estimate deltas decide the rule; the comparison's bootstrap interval is included as
context. Unqualified and incomplete rules are `undetermined` and cannot pass.

Exit codes remain 0 for pass, 1 for paired-coverage or regression failure, 2 for blocked
strict comparison or invalid policy, and 3 for indeterminate policy data. Blocked comparison
and paired-coverage outcomes retain precedence. Omitting a regression policy preserves the
prior comparison exit behavior. See [regression policies](../../../regression-policies.md).
