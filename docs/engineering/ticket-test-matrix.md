# Ticket-test matrix

Started for Prompt 22 (22-T1, 22-T2), then extended by Prompts 24–28. Every implemented
ticket from Prompts 00–20 plus completed checkpoint/extension tickets maps to its intended
behaviour, main paths, specification section, gates, the tests that exercise it, and the
result of actually running them. Prompt 21 was not started, so it has no rows.

## How this matrix was produced

- **Rows.** Rows were drafted from `tickets.md`, each phase report and the code. Every
  cited test was checked to exist with `grep`, and every path to exist on disk. Ticket IDs
  are preserved as recorded, including `17-P18`, which is recorded in `phase-status.md`
  rather than the tickets table.
- **"Result (executed)".** This column comes from JUnit reports, not from phase reports:
  - The full suite, run once on 2026-09-25 with
    `.venv/Scripts/python -m pytest -q -p no:cacheprovider -rs --junitxml=docs/engineering/evidence/22/full-suite-junit.xml`
    (Windows 11, Python 3.12.10). This run started before the 22-T3 engine fix. The tests
    affected by that fix were rerun after it; see report 22 §2.
  - The clean-install E2E suite, `scripts/e2e_suite.py`
    (`docs/engineering/evidence/22/e2e-junit.xml`).

  "N passed" counts the distinct cited tests. A parametrized test passes only if every
  instance passed. "not run" means the cited test produced no JUnit entry.
- **Value class** (22-T5) is an audit judgement against the product purpose: a
  conversational benchmark operator. It is a recommendation for review, not a change.
  Nothing was removed.

## Findings

1. **The LLM planner is not in the product loop.** `plan_with_model` is called only from `aibench plan` (`src/aibench/cli/plan.py:280`, `:409`). Chat drafts always use the template (`src/aibench/sessions/drafting.py:36`, `:240`, `:258`), and so does `benchmark` (`src/aibench/cli/benchmark.py:129`). 07-T3's bounded model loop, provider and 12-T2's model-planner measurement do not serve the conversational loop. They are candidates to defer.
2. **Stale ticket for compare.** `docs/engineering/tickets.md:156` (11-T3) says "compare explicitly deferred" and "(11 tests)". Compare is implemented at `src/aibench/cli/project.py:389-441`, and `tests/test_cli_project.py:214` `test_compare_uses_stored_runs_and_reports_paired_coverage` exists. `docs/engineering/requirements-matrix.md:74` reflects the new state, so the ledgers disagree.
3. **Ticket and matrix status disagree for the planner.** `tickets.md` 07-T3 says DONE, while `requirements-matrix.md:40` marks "Bounded LLM planner" Partial.
4. **Two planner fixture sets share one scorer.** There is a 10-fixture set inside `tests/test_planner_benchmark.py:46` and a 40-fixture set in `benchmarks/planner/v1`, both scored by `src/aibench/planning/benchmark.py:105,150`. The in-test set's 1.0 scores (report 07) are superseded by v1's 0.81 recall. Merge them or retire the in-test set.
5. **Two independent keyword and negation heuristics.** `src/aibench/conversation/agent.py:215` (`_NEGATIONS` for authorization) and `src/aibench/planning/catalog.py:69` (`_NEGATIONS` for concepts) use different word lists: "wait", "later" and "instead" appear in one list but not the other. The heuristics are English-only; held-out recall drops to 0.50, partly on non-English and paraphrased objectives (`docs/engineering/mvp-acceptance.md:108-113`).
6. **Chat is marked "Verified" on scripted-model evidence only.** `docs/engineering/mvp-acceptance.md:23` marks the persistent chat Verified (scripted model), while conversation-quality metrics are "Not done" (`:76`). Every conversational gate in 08–12 ran against a deterministic fake provider, and no live model was ever called.
7. **The full suite has not run since Prompt 12.** Its 687 passes predate Prompt 13 (`docs/engineering/release-readiness.md:25`; report 13 line 39). Report 09 (589 passes before the last redaction fix), report 10 (621 passes before the `sanitize_value` fix) and report 12 (before the fixture-path follow-up) each close on a full suite that predates their own final fixes.
8. **Gates are unreachable from conversation.** Session drafts cannot declare release gates, so exit code 1 comes only from plan-file runs (`docs/engineering/reports/11.md:148`). This is a missing requirement against E2E-07 parity.
9. **Overlapping entry points.** `aibench benchmark` (`src/aibench/cli/benchmark.py`), `chat --objective --send /run` (`src/aibench/cli/chat.py`) and `plan` + `run` all go from an objective to a run. They share services, but three command surfaces for one loop is overbuilding. `benchmark` is a merge candidate with `chat --send`.
10. **Commits that fail on checkout, and a stale version number.** `29e7716` fails on `reconcile` (`docs/engineering/reports/10.md` §4) and `eef959e` on `services.reports` (`docs/engineering/reports/11.md:152`). `src/aibench/__init__.py:3` is still `0.1.0rc1` after Prompts 14–20, while `release-readiness.md` says the rc1 artifacts predate that work.

## Findings (cross-ticket)

1. **Most of Prompts 16-18 are headless-only, not conversational.** The chat surface covers only `/app`, `/world`, `/compare`, `/integrations` (`src/aibench/tui/commands.py:26-43`). `PlanPatch` has no cache, quota, trace, inspection-source, candidate or episode fields (`src/aibench/core/sessions.py:113-127`). Inspection, traces, caches, quotas, candidates, episodes, both OpenAI bridges and Langfuse cannot be driven from the conversational loop. That undercuts the product thesis for these tickets.
2. **The second ecosystem duplicates an existing metric.** Ragas exposes only `ragas.faithfulness` (`plugins/ragas/src/aibench_ragas/faithfulness.py:269`), the same concept as `deepeval.faithfulness` (`plugins/deepeval/src/aibench_deepeval/faithfulness.py:90`). It adds a cross-framework diagnostic but no new benchmark capability, and it carries an open CVE (reports/14.md §4).
3. **The OpenAI Evals OSS bridge duplicates native checks.** Its allowlist is Match/Includes/FuzzyMatch/JsonMatch (`plugins/openai_evals_oss/src/*/upstream.py:33-36`), which overlaps `native.exact_match` (`src/aibench/evaluators/native.py:43`), yet it adds a new `delegated_suite` run type (`src/aibench/services/delegated.py`). It is a candidate for removal unless there is recorded demand.
4. **18-T3 episodes are a thin overlay on 15-T2, with an overclaim.** Execution is Prompt 15's `per_episode`/`group_id` path (`src/aibench/datasets/episodes.py:33,112`), and the manifest is read only by a validate command (`src/aibench/cli/episodes.py:33`). "Simulator provenance" is a metadata model with no simulator behind it (`src/aibench/core/models.py:611`).
5. **Stale cross-report statements about Prompt 17.** ADR 0016:10 ("Prompt 17 as a whole remains unstarted") and reports/18.md:97 ("Prompt 17 remains NOT_STARTED") contradict phase-status.md:25 (Prompt 17 COMPLETE).
6. **Contradiction on the shared compare test.** reports/17.md:117 says `test_conversation_compare_tool_uses_the_shared_stored_service` "still fails", while reports/20.md:110 says it passed when rerun alone. No report re-establishes the current state after the concurrent `services/comparison.py` edits. That file is also dirty in the working tree now, per the git status at session start.
7. **"Demand-selected" connector without demand evidence.** 17-T3 requires a demand-selected connector, but Langfuse was picked "by default (reversible)" (tickets.md Prompt 17 table; ADR 0017), and no user demand is cited anywhere.
8. **Caching adds known accounting gaps.** Cache hits consume quota tokens (reports/16.md:180), scorer pending entries can accumulate (reports/16.md:181), and the evaluation cache overlaps stored-output rescoring. No full-suite rerun followed the final cache-key fix (reports/16.md:139).
9. **Concentrated complexity in optional scope.** `src/aibench/services/comparison.py` has 2,894 lines, `src/aibench/reporting/statistics.py` 1,087, `src/aibench/experiments/service.py` 1,474 and `src/aibench/services/remote_jobs.py` 824. Prompt 19 has only 7 tests for its 1,474-line service (`tests/test_experiments.py:52-299`).
10. **No live evidence anywhere in 14-20, and "Verified" in the requirements matrix can overstate this.** The live provider, hosted Evals API, live Langfuse, Linux/macOS and Python 3.11 runs were all not run (reports/14 §2, 15 §2, 16 §2, 17 §2). requirements-matrix.md rows 90-108 say "Verified" with qualifiers. 14-T4's "calibration" rests on deterministic local judges only (tickets.md 14-T4).
