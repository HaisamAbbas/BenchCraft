# Prompt 25 — Bounded codebase inspector and evidence-backed profile

Status: COMPLETE for the bounded static repository-inspection scope. This report records
local Windows test evidence only; the full acceptance suite was not rerun.

## 1. Implemented behavior and changed paths

- **25-T1 — bounded static inspection.** Extended the existing Prompt 16 source inspection
  service in `src/aibench/inspection/source.py` with `CodebaseInspector`, `InspectionBudget`,
  a typed `DiscoveryResult`, supported-format declarations, path evidence, and
  explicit skip/usage counts. The approved root is checked against `ExecutionPolicy`; links
  and junctions are not followed. Defaults cap inspection at 5,000 files, 256 KiB per file,
  16 MiB read total, 2,000 directories, 2,000 entries per directory, depth 32 and 2,000
  discoveries. Policy bounds also cap caller-supplied budgets.
- **Supported behavior is deliberately narrow.** Python manifests (`pyproject.toml`,
  `requirements*.txt`), Node `package.json`, and Dockerfiles receive limited field parsing.
  Python imports and `__main__` guards use AST; JavaScript/TypeScript uses bounded static
  import matching. JSONL/JSON/CSV/Parquet and test/evaluation paths are candidates by path
  only. Manifest script names and Python main guards are invocation candidates, never
  validated commands. Unsupported source suffixes such as Rust, Go, Java, C/C++, C#, Ruby,
  PHP and Swift are reported as `unknown` and are not parsed.
- **25-T2 — evidence-backed profile.** `ApplicationProfile.repository_inspection` carries the
  typed inspection result; `ApplicationProfiler` provides a service facade. Findings retain
  relative path/line evidence, `inferred` state and confidence. Declared/observed/unknown
  application claims keep their existing semantics. `src/aibench/cli/inspect.py` uses the
  same services, and `src/aibench/inspection/__init__.py` exposes the new types without
  importing evaluator packages.
- **Untrusted and sensitive content.** Secret-like files and sensitive, generated, hidden,
  and vendored directories are excluded. Repository text is parsed as data; inspection never
  imports or executes project code. Dataset/evaluator/test candidates are not loaded,
  evaluated, or promoted. The fixture includes a misleading prose claim, prompt-injection-like
  text, a secret sentinel, a marker-writing `__main__` body, and unsupported Rust source.
- **Fixture and supporting docs.** Added
  `examples/inspection/repository_profile/` and
  `tests/test_application_profile_discovery.py`; extended `tests/test_source_inspection.py`.
  Updated `docs/support.md`, the Prompt 24 alignment matrix, Prompt 25 ticket/test ledgers,
  and `phase-status.md` to state the implemented boundary and executed evidence. The existing
  requirements-matrix Prompt 25 row was checked against the executed report.

## 4. Limits and decisions

- An import or manifest dependency suggests a capability; it does not prove runtime use.
- A file path suggests a dataset, test, evaluator or invocation candidate; contents, oracle
  quality, compatibility, safety and runtime success remain unverified.
- Script names and entrypoint directives are recorded without command contents. No planner
  shell command is inferred or launched.
- Dynamic imports, plugins loaded by name, unrecognized manifest shapes, unsupported languages
  and parser misses remain unknown. A scan budget can also prevent parsing; the emitted path
  record says when parsing may be limited by budgets.
- Existing Prompt 16 inspection and Prompt 18 candidate review/promotion were reused. No new
  language parser, dataset auto-import, evaluator adapter or black-box mode was added.
- Pre-existing worktree changes outside the Prompt 25 paths were preserved. This report does
  not claim those changes were reviewed or certified.
