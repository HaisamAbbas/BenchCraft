Phase 11 — Evidence reports, command composition, and packaging
Status: COMPLETE

1. Implemented functionality and changed files

- **11-T1 Trustworthy reports.**
  - **Builder.** `services/reports.py` (`build_report`, `report_facts`, `export_report`, `outcome_summary`) builds the report from stored facts only. It never creates a runner, loads an evaluator or starts a plugin environment.
  - **Renderers.** `reporting/render.py` renders JSON, Markdown and static HTML. The HTML has a Content Security Policy and no scripts. Every string is sanitized, then escaped for its format. Every percentage is shown with its fraction.
  - **Metric profiles.** Each run freezes its binding profiles (manifest, parameters, rule) in `RunManifest.parameters.metric_profiles`. Every scoring pass records its own in a `scoring_pass` event, written by `services/scoring.score_recorded_run`. Older runs fall back to profiles derived from their results, and the report says so.
  - **Denominators.** `reporting/aggregation.summarize` adds `planned`/`pending`, so partial snapshots keep unfinished work in every denominator. With `missing="unavailable"`, a rescore of a partial run counts executions that never ran as unavailable.
  - **What else a report states:**
    - application failures separate from evaluator failures (reason codes only);
    - successful-request latency p50/p95 by nearest rank, with its definition;
    - observed cost with accounting completeness, and no total when accounting is incomplete;
    - evidence excerpts, including retrieved context;
    - raw evaluator artifacts by ID and digest only;
    - `--no-content`;
    - provenance.
  - **Release gates.** `core/plans.py` adds `ReleaseGate` and `ExecutablePlan.gates`: `min_pass_rate` and `min_completed_coverage` over selected cases, undecided on a partial snapshot. `engine/compile.py` rejects a pass-rate gate on a binding that has no rule. `schemas/1.0.0/ExecutablePlan.json` is regenerated.
- **11-T2 Conversational analysis.**
  - **New tools** (`conversation/agent.py`):
    - `get_report`, the report's aggregates;
    - `export_report`, which writes only the run's own report and only when the user's words ask for an export.
  - **Claim checking.** `check_claims` links every number in a reply to the query result it came from; the user's words and tool errors are never sources. It flags numbers it cannot trace in the status line. The status line also labels partial snapshots and partial results.
  - **Prompt rules.** The system prompt requires causes to be labelled as hypotheses, with case IDs.
  - **Controller** (`sessions/controller.py`): `report`, `report_facts` and `export_report`. The assistant gets case content only when the policy shares it.
  - **Terminal.** `/report` (`tui/commands.py`, `tui/render.report`) prints the aggregates with denominators and writes HTML and JSON.
- **11-T3 Command composition.**
  - `cli/project.py`: `init`, `doctor` (secrets never printed), `plugins list`, and `compare`, which reports that it is unsupported and exits 2.
  - `cli/benchmark.py`: interactive conversation, `--non-interactive` producing a blocked or `authorization_required` result, and `--auto --policy`.
  - `cli/report.py`: `aibench report`.
  - `cli/run.py`: `run [DIR|DATASET]`, with the plan from the config's new `plan_path`.
  - `cli/chat.py`: `--objective`, and `chat --send` exit codes.
  - `services.runs.run_exit_code`: one §13 mapping for `run`, `resume`, `benchmark --auto` and `chat --send`.
  - Also changed: `config/model.py` (`plan_path`) and `cli/main.py`.
