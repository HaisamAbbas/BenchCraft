2. Code-review findings and remediation (this pass)

- **High — shallow immutability (models.py:23-27).** `frozen=True` blocked attribute
  reassignment but not mutation of a nested mutable object already stored in a field
  (`case.input["nested"].append(...)` used to succeed). Fixed with a new `FrozenValue`
  annotated type in `core/models.py`: a `BeforeValidator` (`deep_freeze`) recursively converts
  dicts to `MappingProxyType`, lists/tuples to `tuple`, sets to `frozenset`, all the way down,
  paired with a `PlainSerializer` (`deep_unfreeze`, `when_used="json"`) so
  `model_dump(mode="json")` and JSON Schema are unaffected. Applied to every loosely-typed
  field on `BenchmarkCase` (`input`, `expectations`, `metadata`, `extensions`), `Fixture.content`,
  `EvaluationPlan` (`bindings`/`selectors`/`sampling`/`aggregations`/`gates`/`budgets`/
  `metric_specs`), `ApplicationSpec` (`input_binding`/`output_binding`), `ExecutionResult`
  (`output`/`usage`/`timing`/`tool_events`/`observation_completeness`), `EvaluationResult`
  (`provenance`/`uncertainty`/`resources`), `RunManifest` (`plugin_hashes`/`model_identifiers`/
  `parameters`/`environment`). `BenchmarkCase.application_input_projection()` now calls
  `deep_unfreeze()` before returning, so runners get an ordinary mutable, JSON-serializable
  copy — mutating it never touches the frozen Golden.
- **High — ingestion not bounded-memory (ingest.py:28-34, 67-69; test_ingest.py:68-85).**
  `ingest_dataset()` retained every normalized case unconditionally. Added a `retain_cases: bool`
  parameter (default `True`, an explicit full-load mode documented as such) plus
  `max_errors`/`max_warnings` caps with truncation flags. `retain_cases=False` keeps only
  running manifest/dedup state (case IDs, not full case bodies) and returns `cases=[]`.
  `src/aibench/cli/dataset.py` now calls `ingest_dataset(path, retain_cases=False)` since the
  CLI only needs counts/errors/warnings. Old memory test (which only asserted a loose
  file-size multiple, without ever using non-retaining mode) replaced with
  `tests/test_ingest.py::test_bounded_memory_with_retain_cases_false`, which measures the SAME
  3,000-case generated dataset under both modes and asserts `retain_cases=False` peak memory
  stays under 60% of `retain_cases=True` peak. Actual measured result:
  `retain_cases=True` peak 7,245,154 bytes vs `retain_cases=False` peak 373,689 bytes
  (ratio ≈ 0.052, ~19x less).
- **High — malformed nested input could crash instead of producing a line error
  (normalize.py:117-159; ingest.py:83-87).** Fixed in `datasets/normalize.py`:
  `_normalize_fixtures()` now explicitly rejects non-object `fixtures` entries and entries
  missing `name` with a clear `ValidationError` (previously `f["name"]` on a non-dict raised a
  raw `TypeError`); `reference`/`provenance`/`expectations`/`metadata` are now explicitly type
  checked before use (previously a non-dict `reference` or `provenance` was silently ignored
  instead of rejected); the final `ReferenceAnswer(...)`/`Provenance(...)`/`BenchmarkCase(...)`
  construction is wrapped in `try/except PydanticValidationError`, converting any remaining
  nested-type mismatch (e.g. `context: [1]`, a non-`str` list item) into our own line-numbered
  `ValidationError` instead of letting a raw `pydantic.ValidationError` propagate.
  `datasets/ingest.py` additionally catches `(PydanticValidationError, TypeError, KeyError,
  AttributeError, ValueError)` as a documented defense-in-depth boundary so one malformed line
  can never abort the whole ingestion or crash the CLI with a framework traceback, even from an
  unanticipated edge case. Verified end-to-end through the real CLI on
  `examples/datasets/invalid.nested.jsonl` (bad `fixtures`, `context`, `reference`,
  `provenance`, and a non-namespaced `extensions` key on five separate lines): exit 2, five
  clean line-numbered errors, zero tracebacks.
- **Medium — extension namespace validation missing (normalize.py:153-155;
  test_normalize.py:65-69).** `datasets/normalize.py` now requires every `extensions` key to
  match `^[A-Za-z][A-Za-z0-9_]*[.:][A-Za-z][A-Za-z0-9_]*$` (e.g. `acme.priority` or
  `acme:priority`); a bare key like `made_up_field` is rejected with a clear message instead of
  being silently accepted. The test that previously accepted a bare key was replaced with
  `test_namespaced_extension_key_is_accepted` / `test_non_namespaced_extension_key_is_rejected`
  / `test_colon_namespaced_extension_key_is_accepted`.
- **Medium — missing identity fields (models.py:184-202, 223-237, 281-288).** Added
  `ApplicationSpec.application_id`, `ObservationClaim.observation_id`,
  `ExecutionResult.execution_id` (plus a `ExecutionResult.build_id(run_id, case_id,
  repetition_id, attempt_id)` helper for the canonical composite form), and
  `ArtifactRef.artifact_id` (distinct from the content `digest`, since two `ArtifactRef`
  records can share content but not identity). All four are now required fields.
  `tests/test_models.py::test_identity_fields_are_required` asserts construction without
  `artifact_id` fails.
- **Reviewer's Windows temp-directory issue** (their environment's system `%TEMP%` was
  inaccessible to the pytest process, producing `45 passed, 10 errors` instead of a clean run).
  Added `tests/conftest.py::pytest_configure`, which points pytest's `basetemp` at a
  repo-local, gitignored `.pytest-tmp/` directory instead of the system temp directory, so the
  suite no longer depends on system temp-directory permissions.

3. Second review and Pass 2 remediation

A second review confirmed the five original findings were substantially fixed, and correctly
identified two remaining gaps in Pass 1's own fixes:

- **The `.pytest-tmp` fix still failed in the reviewer's sandbox.** Pass 1's `conftest.py`
  pointed `basetemp` at a single fixed `<repo>/.pytest-tmp` directory. In a sandbox that
  restricts filesystem writes to a specific allow-listed location, a fixed path chosen from
  inside the repository is not guaranteed writable regardless of which path is chosen — and,
  separately, a fixed path reused across runs risks being created under one process's
  permissions and then written into by another, unrelated to the sandbox issue but a real bug
  in its own right. Rewrote `tests/conftest.py` to: (1) honor an explicit
  `AIBENCH_TEST_TMPDIR` environment variable first, for a sandbox that knows its own writable
  scratch path; (2) otherwise probe a **freshly uuid-suffixed** subdirectory under
  `<repo>/.pytest-tmp/` with an actual write-then-delete, never an assumption; (3) otherwise
  probe a fresh `tempfile.mkdtemp()` location; (4) if nothing is writable, leave `basetemp`
  untouched rather than raise, so a fully restricted sandbox gets pytest's own default instead
  of a conftest crash on top of it. This is honestly best-effort: if the reviewer's sandbox
  structurally disallows all repository-adjacent and system-temp writes for the pytest
  subprocess, no code change inside this repository can fix that — the documented
  `AIBENCH_TEST_TMPDIR` override exists precisely for that case, and
  `docs/engineering/implementation-contract.md`'s standard check convention now mentions it.
- **The duplicate-ID index was still an unbounded in-memory dict (`ingest.py:99`,
  `seen_at_line`).** Even with `retain_cases=False` no longer retaining full case bodies,
  every distinct case ID still had to live in a Python dict for the whole ingestion, so peak
  memory still grew with the number of distinct IDs — the review's precise, correct point.
  Added `_DedupIndex` in `src/aibench/datasets/ingest.py`: an in-memory dict by default (cheap,
  fine for ordinary datasets), or a temporary on-disk SQLite table when the source file exceeds
  `large_file_threshold_bytes` (default 50 MB, per §6's "use an on-disk index for very large
  files") or when `force_disk_backed_dedup=True` is passed explicitly. `IngestReport` gained a
  `dedup_disk_backed: bool` field, and `aibench dataset validate` now reports when it engaged.
  Measured on 20,000 distinct case IDs with otherwise-tiny content (isolating duplicate-ID
  tracking memory from case-body retention): in-memory dict peak ≈ 3.4 MB vs. disk-backed peak
  ≈ 56 KB (~60x less). `retain_cases=False` + disk-backed dedup together now keep peak process
  memory bounded by `max_errors`/`max_warnings` plus a small constant, independent of both
  dataset content size and the number of distinct case IDs — not merely "narrowed and
  documented" scope, but the actual disk-backed index the review suggested as the preferred
  fix.

6. Decisions or specification discrepancies recorded

- Extension key namespacing (`vendor.field` / `vendor:field`) is an engineering interpretation
  of the specification's "Custom fields belong in namespaced `extensions`" sentence (§6), which
  does not itself prescribe a concrete key syntax. Chose a permissive two-segment pattern
  rather than a fixed vendor registry, since MVP has no such registry yet. Not filed as a
  separate ADR (routine implementation choice per the engineering contract); recorded here so
  the convention isn't silently assumed elsewhere.
- `ExecutionResult.observation_completeness` changed from `dict[str, ObservationState]` to the
  generic `FrozenValue` (`Any`) to close the same mutability gap as the other dict fields; this
  trades away Pydantic-level enum validation on that field's values in exchange for true
  immutability. No code yet writes to this field (it is populated starting in Prompt 03), so
  the trade is low-risk today; flagged here so Prompt 03 validates values explicitly if it
  matters there.
- `retain_cases=True` remains the `ingest_dataset()` default (matches prior behavior for
  existing callers/tests); only the CLI path was switched to `retain_cases=False`. This is a
  deliberate, documented split between "give me the parsed dataset" (API default) and "just
  validate/summarize this, possibly huge, file" (CLI), not an oversight.
- The disk-backed dedup index switches automatically at a 50 MB file-size threshold
  (`large_file_threshold_bytes`, overridable per call). A size-based heuristic rather than a
  case-count-based one, since file size is known instantly via `stat()` before streaming
  begins, whereas case count is only known after a full pass. Recorded here as a routine
  implementation choice; revisit the threshold value if Prompt 12's 100-case/large-scale
  acceptance testing shows it should be lower or configurable via CLI flag/config.
- The SQLite-backed index commits only once (implicitly, by leaving the transaction open for
  the connection's own lifetime) rather than per insert, since it is a throwaway scratch file
  deleted in `close()` and the same connection can read its own uncommitted writes. Recorded
  because it is a deliberate durability trade-off (irrelevant here — nothing outlives the
  connection) rather than an oversight.
