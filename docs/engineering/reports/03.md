Phase 03 — Application runners and observation capture
Status: COMPLETE

1. Implemented functionality and changed files

- **03-T1 Runner lifecycle.**
  - `describe → prepare → healthcheck → invoke → reset → close` in `src/aibench/runners/base.py`. Every operation is time-bounded.
  - `invoke` can be cancelled cooperatively (`InvocationContext.cancel`, which produces a recorded `cancelled` attempt) or by task cancellation (which cleans up, then re-raises).
  - Runners never retry. Each attempt records `error_kind`, `effect_state` and `correlation_id`.
  - Runners only ever receive `AppInputEnvelope` (`BenchmarkCase.application_input_projection()`). JSON Pointer input/output bindings are in `src/aibench/runners/bindings.py`.
  - Core models (`src/aibench/core/models.py`): `CliTransport`, `HttpTransport`, `HttpSecretHeader`, `ErrorKind`, `EffectState`, the optional `ApplicationSpec.transport`, and three optional `ExecutionResult` fields.
- **03-T2 CLI transport** (`src/aibench/runners/cli_runner.py`, `process_tree.py`).
  - argv only, no shell, JSON on stdin, JSON or explicit legacy text on stdout.
  - Capped stdout; exceeding the cap kills the process (`output_limit`). Stderr keeps a bounded prefix.
  - Child environment is an allow-list plus explicit `env` / `secret_env`. Secrets are redacted in captures.
  - Process-tree cleanup: Windows Job Object, POSIX process group. The tree is killed at the end of every invocation.
  - Explicit trusted-local mode is required.
- **03-T3 HTTP transport** (`src/aibench/runners/http_runner.py`, `src/aibench/security/endpoints.py`, `src/aibench/security/secrets.py`).
  - Secret-reference headers; TLS verification on by default, optional CA bundle; `trust_env=False`.
  - Endpoint policy checked on every URL and every redirect hop. Plain http is loopback-only by default. Redirects are refused unless enabled, and then only 307/308 within policy.
  - Request/response size caps, a single deadline for the whole exchange, and an `X-Request-ID` correlation header.
  - Dispatch is tracked through httpcore's trace, so failures before dispatch are `not_dispatched` and failures after it are `unknown`.
- **03-T4 Fixtures, persistence, smoke path.**
  - `examples/apps/`: `cli_chatbot.py`, `blackbox_cli.py` (text mode), `http_rag_app.py` (returns the documents it actually retrieved), `effect_counter_app.py` (counts effects; its delay mode applies the effect before responding), plus `*.app.json` configs and `examples/datasets/booking.valid.jsonl`.
  - `src/aibench/services/execution.py`:
    - `invoke_and_record` writes artifacts first, then the result.
    - `run_developer_smoke` labels its manifest `developer_smoke`: no scheduler, retries or evaluation.
  - `src/aibench/cli/app.py`: `aibench app describe` (observability-gap report) and `aibench app smoke`.

- **Independent review:** an adversarial subagent reviewed the diff.
  - Three major findings were confirmed and fixed with regression tests: hostile JSON crashing an invocation; a lone surrogate breaking the result commit; stdout lost when a descendant outside containment held the pipe.
  - Also fixed: gateway 5xx reported as `completed`; redaction gaps; secret headers sent across origins on redirects.
  - Two findings were accepted and documented in the ADR: the POSIX PGID reuse window, and the approximate decompression cap.
  - One claim was rejected with evidence: it called the `proc.wait()` comment wrong, but CPython 3.12 wakes exit waiters only in `_call_connection_lost`, and a direct experiment showed `wait()` blocking while a grandchild held the pipe.
- **Found during implementation and fixed:**
  - `DatasetManifest.created_at` changes on every ingest, so a second smoke run on the same dataset would conflict. The service now reuses the stored manifest.
  - `time.monotonic()` has about 15.6 ms resolution on Windows; wall time now uses `perf_counter()`.
