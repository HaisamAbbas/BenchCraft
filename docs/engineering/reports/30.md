# Prompt 30 — Close the repository-to-conversation acceptance gap

Status: **COMPLETE.** The approved-root repository findings now enter the shared planning
profile used by a fresh conversation. Prompt 29's missing journey is included in the
repository-defined clean-install suite as E2E-08.

## Implemented delta

`planning.service.gather_inputs` accepts an optional source root. It runs the existing
`CodebaseInspector` only when the current policy approves inspection of that root, attaches
the bounded `SourceInspection` to the existing `inspect_application` profile, and preserves
policy denial as an explicit note. Session drafting supplies its project root; headless plan
and benchmark commands supply their current working directory. This reuses Prompt 25 services
and does not introduce another parser, profile model, or execution path.

The fresh-chat fixture shows path/line-backed inferred findings and unsupported-language
unknowns, rejects a run request assembled from source prompt-injection text, and keeps a
secret sentinel and source body out of the assistant briefing. It then executes the
user-authorized configured application through the existing validated plan, reopens the
session, reports stored results, and rescores the same run without a second application call.
