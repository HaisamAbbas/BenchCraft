Phase 04 — Evaluator contracts, native checks, and registry
Status: COMPLETE

1. Implemented functionality and changed files

- **04-T1 Evaluator protocol.**
  - Contracts in `src/aibench/core/models.py`: `EvaluatorManifest`, `MetricBinding`, `DecisionRule` (strict, finite threshold), `FieldRequirement`, `MetricDirection`, `MetricScope`.
  - `EvaluationResult` gains identity, scope, rule, reason and `scoring_id` fields. `RunManifest.application_id` is added.
  - `src/aibench/evaluators/protocol.py` provides the `Evaluator` ABC (describe / validate_binding / required_fields / prepare / evaluate / evaluate_batch / close), `EvaluationView` (canonical paths, missing vs empty, path validation), `EvaluatorContext` (cancellation, verified artifact writing, usage accounting) and `EvaluationOutcome`.
  - `evaluators/validation.py` checks params against the manifest schema and rules against the value kind. It uses a jsonschema registry that refuses remote retrieval, and validates regex schemas in a killable worker (`evaluators/schema_worker.py`).
- **04-T2 Registry and controlled discovery** (`src/aibench/registry/__init__.py`, `discovery.py`, `worker.py`).
  - Namespaced IDs, resolvable as `id`, `id@major`, `id@major.minor` or an exact version; resolution is numeric.
  - `core_schema` range checks; the `native.*` namespace is reserved.
  - Binding validation collects every problem before anything runs: params, rule versus kind, invalid schema, unknown ID, requirement paths, duplicate resolved bindings, and observations the run's application doesn't expose.
  - Entry-point discovery reads metadata only. Manifests are loaded in a subprocess worker with a tree-killing timeout and an output cap (`runners/process_tree.py::run_contained`).
  - Third-party evaluators are listable but never instantiated in-process. Local evaluator files require `--trust-local-code`.
- **04-T3 Evaluators** (`src/aibench/evaluators/native.py`, `examples/evaluators/refund_window.py`).
  - `native.exact_match` (boolean): normalization options; a non-text answer is a failure.
  - `native.json_schema` (boolean): the schema is inline or read from a case field; violations are kept as a raw artifact.
  - Domain example `acme.refund_window` (category): `correct`, `wrong_window`, `no_window_stated` or `unusable_output`.
- **04-T4 Normalize, persist, aggregate** (`src/aibench/services/scoring.py`, `src/aibench/reporting/aggregation.py`).
  - Scores recorded executions only; there's no runner in the call graph.
  - Final-attempt selection rule; one honest status per selected execution per binding; decisions come from the frozen rule; conformance checks.
  - Resources and accounting are recorded, with unknown model usage stored as null, and reported usage is stored as `UsageEvent`s.
  - Persisted as `evaluation_attempts` and `metric_results`, keyed per scoring pass.
  - Deterministic per-binding summaries with explicit denominators and coverage, and no cross-metric score.
  - Storage (`storage/migrations.py` migration 4, `storage/repositories.py`): attempts are keyed by (run, case, repetition, metric, binding, attempt), and results can be read per scoring pass.
- **CLI** (`src/aibench/cli/score.py`, registered in `cli/main.py`): `aibench evaluators list|describe|plugin` and `aibench score RUN_ID --metrics FILE [--custom-evaluator F --trust-local-code] [--json]`.
- **Dependencies:** `pyproject.toml` adds `jsonschema>=4.23,<5`; `requirements-dev.lock.txt` gains 5 packages.
- **Schemas:** new `schemas/1.0.0/{DecisionRule,EvaluatorManifest,FieldRequirement,MetricBinding}.json`; updated `EvaluationResult` and `RunManifest`.
- **Examples:** `examples/datasets/support.valid.jsonl`, `examples/metrics/support.metrics.json`.

4. Decisions or specification discrepancies recorded

- **`docs/adr/0003-evaluator-protocol-registry-and-scoring.md`:** contracts live in core; the harness owns decisions; the status taxonomy; the selection rule (and why Prompt 06 must select from work items); identity and rescoring; the aggregation contract; accounting; discovery through worker isolation (process only, not a sandbox); jsonschema as a dependency; the remote-`$ref` egress fix; migration 4; and the review changes.
- **Security findings fixed in this phase:**
  - jsonschema fetched remote `$ref` URLs over the network by default. Found by a local-server test and fixed.
  - An untrusted regex could stall scoring without bound. Fixed by the killable worker.
- **Independent review:** every finding was reproduced by a failing test and then fixed. That includes the blocker, where an unusable answer counted as `not_applicable` and so inflated the pass rate. See ADR 0003.
- **Second review (P2, P3), both reproduced and then fixed:**
  - Failures in `prepare()` or `close()` could abort a pass. Now `prepare()` failures become recorded errors, and `close()` failures become report warnings.
  - The worker output cap was applied only after output had been written to temp files. It's now enforced live, and the worker is killed at the cap.
  - Tests: `test_prepare_and_close_failures_never_abort_the_pass` and `test_worker_output_cap_is_enforced_while_the_worker_runs`. Before the fix, the flood test ran its full 60s timeout.
- **Accepted limit:** a trusted local evaluator that blocks the event loop synchronously can't be interrupted. Hard limits for arbitrary evaluator code come with Prompt 05's worker execution.
