1. Implemented functionality and changed files

- **15-T1: new transports**, all behind the existing runner contract.
  - **Python callable** (`runner: python`): `src/aibench/runners/python_runner.py` and the standard-library shim `python_shim.py`.
    - The callable runs in a fresh process of the application's own interpreter, so the CLI protocol's bounds apply.
    - Input and output are UTF-8. The callable's prints go to stderr, and the shim's directory is kept off `sys.path`.
  - **OpenAI-compatible endpoint** (`runner: openai_compatible`): `runners/openai_runner.py`, an HTTP runner with a chat-payload builder.
    - Default bindings read the answer, `usage` and `tool_calls` (`ApplicationSpec.effective_output_binding`).
    - Tool calls are recorded as requests, never as effects.
  - **Container** (`runner: container`): `runners/container_runner.py`.
    - Configuration: an image pinned by digest (`--pull=never` on each run); a fixed host `docker` client; non-root uid and gid; `--read-only`, `--cap-drop ALL`, `no-new-privileges`; tmpfs scratch space and read-only bind mounts (CSV-quoted); memory, CPU and pids limits; `--network none` unless the policy allows `bridge`.
    - App config cannot choose a host executable or override host-sensitive engine-client environment variables (`PATH`, dynamic-loader variables, `DOCKER_HOST`, and related names).
    - Mounting the engine socket is refused, both in the config and on the resolved path.
    - Each container is removed after every invocation, including on timeout or cancellation.
  - **Shared plumbing:**
    - `CliRunner` and `HttpRunner` accept a derived transport; `CliRunner` gains `_argv_for`.
    - `BaseRunner.reset(seed)` and `resettable`.
    - `runners.reset_hook`, and factory wiring.
    - Models in `core/models.py`: `PythonTransport`, `ContainerTransport`, `ContainerMount`, `OpenAICompatibleTransport`, `CliTransport.reset_argv`.
    - Policy in `security/policy.py`: `allowed_container_images`, `allow_container_network`, `allowed_test_worlds`, and `policy_matches`.
- **15-T2: stateful outcomes.**
  - **State between cases.**
    - `engine/engine.py` resets per case or per episode: an episode is the cases sharing a `group_id`, run in order.
    - Each reset is an `app_reset` event.
    - A failed reset blocks the case; a reset is abandoned on cancel.
    - A failed or interrupted turn blocks the rest of its episode.
  - **Compile rules** (`engine/compile.py`):
    - a test world must be declared, approved, loadable through a hook, and not on a `shared` app;
    - a seed must be an object or list, inside the application's directory;
    - episodes allow no retries, and a selection can't split an episode;
    - an app with a reset hook needs application concurrency 1.
  - **Run manifest** (`services/runs.py`): the reset mode and a frozen world seed, verified on resume.
  - **Reports:** the report's `application.state` and a Markdown/HTML row.
  - **Observations:** a `world_state` observation (bindings, `ExecutionResult`, evaluator view, registry).
  - **Evaluators** (`evaluators/agent.py`): `native.tool_calls`, `native.tool_outcomes` and `native.final_state`, with a tool-event parser and JSON-strict constraints. Planner concept `task_outcome`.
- **15-T3: chat.**
  - **Describing the app:** `services/applications.describe_application`, used by `aibench app describe [--policy]`, `/app` and the assistant's `describe_application` tool.
  - **Choosing a test world:** `/world NAME|none` and `PlanPatch.test_world` / `clear_test_world`, through `SessionChoices`, the draft and the plan. The assistant must be quoting a world the user named. The plan card shows the world.
  - **Stateful drafts:** a draft for a stateful app gets concurrency 1, and no retries for episodes (`planning/service.state_limits`).
- **Fixtures:**

4. Decisions or specification discrepancies recorded

- **ADR 0014** records these decisions:
  - Transports reuse the CLI and HTTP protocols. A callable runs in a subprocess shim, never in-process.
  - A container is a configured sandbox, approved by image instead of trusted-local mode. It is not a hostile multi-tenant boundary.
  - The reset modes, episode rules, concurrency 1 for stateful apps, and test worlds frozen with the run.
  - Three separate outcome metrics; a single combined score was rejected.
  - Chat selection goes through the validated plan-change path.
- **Behaviour change:** an application that declared `reset_url` is now actually reset, and needs application concurrency 1.
- **Review fixes, all with regression tests:**
  - uid and gid parsed numerically;
  - strict container-path syntax, CSV-quoted mount sources, and a socket check on normalized and resolved paths;
  - the application config cannot select the host engine executable or inject host-sensitive environment variables into its client; each run explicitly refuses pulls, even if the image disappears after preflight;
  - the UTF-8 shim, prints to stderr, no `sys.path` shadowing;
  - `shared` with a test world refused;
  - episode-splitting selections refused;
  - seeds must be objects or lists inside the app directory;
  - `present: false` means absent, and constraints are JSON-strict (`true` is not `1`);
  - a reset is abandoned on cancel, and the case is cancelled.
- **Recorded, not changed:** a reset is bounded by the fixed 10-second lifecycle timeout.
- **Ordering:** Prompt 14, the prerequisite, was implemented in parallel by another session and is now marked COMPLETE there. Prompt 15 doesn't consume its contracts, and none of its files were changed.
- **Test tolerance:** the ConPTY chat start-up wait went from 12 s to 45 s, with the measurement recorded in the test.
