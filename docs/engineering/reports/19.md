# Phase 19 — Controlled optimization experiments

Status: COMPLETE

## 1. Implemented functionality and changed files

- **19-T1 — Explicit experiment contract.** Added finite exposed application settings,
  objective metrics, constraints, development and protected-holdout datasets, intended-change
  text, and run budgets in `src/aibench/core/models.py`. `src/aibench/experiments/service.py`
  validates and freezes the contract. Migration 11 stores experiment definitions, trial
  lineage, append-only events, and protected dataset digests in
  `src/aibench/storage/migrations.py` and `src/aibench/storage/repositories.py`.
- **19-T2 — Controlled trials and protected evaluation.** The experiment service materializes
  a bounded deterministic grid and reuses `src/aibench/services/runs.py` with stable trial
  and run identities, exact parameter maps and hashes, a fixed seed, frozen plan/evaluator/
  application/policy identities, and declared budgets. Development-only selection uses the
  shared strict comparison service and paired uncertainty intervals. The selected candidate
  is durably locked before the service compiles a separate holdout plan. It then runs the
  baseline and selected configuration once on the protected holdout; the report keeps that
  final evaluation distinct from development selection. Boolean objectives are compared as
  paired binary rates.
- **19-T3 — Conversational control and adoption proposal.** Added
  `src/aibench/cli/experiments.py`, CLI registration in `src/aibench/cli/main.py`, and
  conversation tools in `src/aibench/conversation/agent.py` for experiment state and
  adoption proposals. Reports explain the tradeoffs and proposals are audit-recorded
  recommendations; they do not edit app source, deploy, or write production configuration.
- **Examples, tests, and documentation.** Added the deterministic known-objective fixture in
  `examples/experiments/known_objective/`, `tests/test_experiments.py`, and schemas for the
  experiment models under `schemas/1.0.0/`. Added ADR 0018, the experiment guide, changelog
  and upgrade notes; updated `docs/engineering/tickets.md`,
  `docs/engineering/requirements-matrix.md`, and `docs/engineering/phase-status.md`.

## 4. Decisions or specification discrepancies recorded

`docs/adr/0018-controlled-experiments-and-protected-holdout.md` records the finite exposed-
parameter boundary, deterministic bounded grid, uncertainty-qualified development selection,
durable selection lock, one-time protected evaluation, paired binary-rate handling, and
proposal-only adoption behavior. This keeps the optional optimizer from using hidden labels
to steer its search. If the final holdout is inconclusive, the system recommends retaining the
baseline; another experiment requires a separately authorized run and a fresh holdout.

Prompt 20 material; this Prompt 19 implementation and report do not claim or extend that work.
