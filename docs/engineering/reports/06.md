1. Implemented functionality and changed files

- **06-T1 Compile and schedule.**
  - `src/aibench/core/plans.py` defines `ExecutablePlan` and its settings: selection, concurrency, retry, budgets and plugin environments. Its JSON Schema is exported as `schemas/1.0.0/ExecutablePlan.json`.
  - `src/aibench/engine/compile.py` validates and applies policy in a fixed order (policy → application → plugin loading → bindings → evaluator policy) and collects all problems together.
  - `src/aibench/engine/engine.py` (`RunEngine`) builds a work graph of execution and evaluation items with dependencies, keeps per-role concurrency caps, and uses one writer with compare-and-set transitions.
  - Storage adds `transition_work_item`, `append_run_event`/`list_run_events`, and the run lease (`acquire`/`heartbeat`/`release_run_lease`), backed by migration 5 (`run_events`) and migration 6 (`run_leases`).
- **06-T2 Policy and accounting.**
  - `src/aibench/security/policy.py` covers:
    - approved application IDs and HTTP origins (loopback by default)
    - trusted-local mode
    - maximum effect level
    - evaluator allow-list and model-evaluator (data egress) permission
    - plugin interpreters and plugin import paths
    - secret references
    - `data_roots`
    - budget ceilings
  - `src/aibench/engine/budget.py` reserves budget before dispatch and reconciles after. Application, evaluator and planner are tracked separately.
    - Hard limits: calls, judge tokens, wall time.
    - Soft limit: cost, labelled an estimate.
    - Unknown cost or tokens are never counted as zero.
    - Resume replays all prior spend.
- **06-T3 Attempts and retries.**
  - `src/aibench/engine/retry.py` retries transient failures only when no effect could have happened.
    - Unknown effects are final.
    - Evaluations are never retried when the evaluator retries internally.
    - Low scores are never retried.
    - Backoff is seeded, capped, and honours Retry-After.
  - `runners/http_runner.py` records `retry_after_seconds`.
  - Every attempt is committed with its cost, and application usage is recorded as `UsageEvent`s.
- **06-T4 Commands and control.**
  - `src/aibench/services/runs.py` covers:
    - `create_run`: freezes the plan and application spec as artifacts, writes the manifest, approval and work items
    - `execute_run`: takes the lease, verifies identities, recovers in-flight work conservatively, replays prior spend
    - `run_status`, `evaluate_run`
  - `src/aibench/cli/run.py` adds `plan validate`, `run --plan`, `resume`, `evaluate` and `runs status`, with exit codes 0/2/3/4/130.
  - `RunController` provides pause, resume, cancel and interrupt (a second interrupt aborts in-flight work but the run stays resumable). It is thread-safe, and requests made during setup are honoured.

4. Decisions or specification discrepancies recorded

- **ADR 0005** records the plan format and compile order; policy dimensions and defaults; freezing and identity verification; the engine's single-writer design (compare-and-set plus run lease); run control semantics; budget semantics; retry rules; conservative recovery; exit codes; and limits.
- **Moved forward from Prompt 08:** `run_events` (migration 5) and `run_leases` (migration 6) are needed for durable events and single-session enforcement. Sessions, conversation turns and decision tables stay with Prompt 08.
- **No exactly-once promise** (in scope for this prompt). Effect-free work may repeat after a crash (at-least-once, and every attempt is recorded). Ambiguous effectful work stops at `unknown_effect`. Rescores never produce new latency samples.
- **Documented limits:**
  - `max_judge_tokens` can be exceeded by in-flight evaluations (bounded by evaluation concurrency).
  - When `data_roots` is unset, local files are not restricted.
  - Lease staleness is local: pid liveness on the same host, or a 60 s TTL.
- **Independent review:** a subagent reviewed the work adversarially. All 7 major findings were reproduced and fixed:
  1. No run lease: a concurrent `resume` re-dispatched live in-flight work. Fixed with migration 6 and a heartbeated lease.
  2. A call dispatched before a crash was not counted, so the hard call limit could be exceeded. Now counted, and recorded in the `recovered` event.
  3. Judge tokens reset on resume. Fixed by replaying every committed attempt.
  4. Recovery retried past `max_attempts`.
  5. Plugin import paths bypassed the policy. They now have their own allow-list.
  6. Unknown cost counted as $0 against the soft limit, and a known cost was dropped when mixed with an unknown one. The plan now requires estimates, and unknown-cost calls without one are reported as `unenforced`.
  7. Editing an app config broke later runs. The spec is now frozen as an artifact per run.
- **Minor review findings, fixed:**
  - Cancelling during backoff stranded pending items.
  - A second interrupt cancelled unstarted work; it now leaves it resumable.
  - Wall time was double-counted across sessions; sessions now record their own elapsed time, and a dead session's time comes from its lease.
  - An interrupt finalized transient evaluation failures.
  - A signal during setup was lost.
  - The CLI created a workspace on read commands and printed tracebacks for storage or registry errors; it now exits 130 on Ctrl+C before dispatch.
  - No data-scope policy existed; `data_roots` was added.
  - Two tests passed vacuously, and evaluation-cap and backoff-cancel tests were missing.
  - `_settle_undispatchable` had dead code.
- **Found while verifying:**
  - The CLI printed "projected cost $0.0" when the application's cost was unknown. It now shows known cost plus the count of unknown-cost calls, and any unenforced limits.
  - `python -m build` (setuptools sdist) leaves an `aibench-0.1.0/` staging directory in the repo root on this machine, because another process holds its files open. The leftovers were removed, and `/aibench-*/` is now git-ignored. Earlier prompts' builds were probably affected too.
