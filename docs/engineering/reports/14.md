# Phase 14 — Second evaluator ecosystem and comparisons

Status: COMPLETE (local source/test validation; clean post-audit wheel rebuild and optional live/platform checks remain pending)

## 1. Implemented functionality and changed files

- **14-T1 — Ragas adapter:** Added the separately installable `plugins/ragas/` package, pinned and runtime-checked against the real `ragas==0.4.3` collection API (`Faithfulness.ascore` and `InstructorBaseRagasLLM`). The adapter consumes recorded `case.input`, `execution.output`, and observed retrieved text only; it never substitutes Golden reference context, maps non-finite/no-statement results to `not_applicable`, preserves raw Ragas evidence, sets `RAGAS_DO_NOT_TRACK=true`, and runs in a separate worker. Added real structured-output judge fixtures under `tests/fixtures/ragas_judges/` and contract tests in `tests/test_ragas_adapter.py`; plugin startup bounds are now carried by `PluginEnvironmentRef` and exposed by `aibench score --plugin-startup-timeout`.
- **14-T2 — Comparable accounting:** Added `EvaluationCompatibilityIdentity`/`IdentityComponent`, frozen scoring-pass profiles and result provenance in `src/aibench/core/models.py` and `src/aibench/services/scoring.py`. Added the read-only `src/aibench/services/comparison.py` service with dataset/case-content, repetition-policy, frozen application-artifact, application-instrumentation, metric/plugin/package, judge, rubric, dependency, plan, pass-completion, and execution-lineage checks. Strict comparisons fail closed for unknown, legacy, compact, or result-inconsistent identities; a rescore freezes the dependency identity it actually resolved, and completed-pass evidence is recorded.
- **14-T3 — Statistics and shared workflow:** Added `src/aibench/reporting/statistics.py` for case-macro paired deltas, coverage denominators (including unpaired selected units), seeded grouped/cluster bootstrap intervals, and repeated-judge stability that excludes cached copies. Wired one service into `aibench compare`, the session `compare_runs` tool, and `/compare`; the public comparison path opens SQLite and artifacts read-only, and assistant projections remove case/group IDs, hashes, raw ledgers, and judge/rubric configuration. Added CLI/TUI/conversation/session integration tests.
- **14-T4 — Independence/calibration evidence:** Added `tests/test_cross_ecosystem.py`, which loads the real DeepEval and Ragas plugin interpreters, scores the same stored executions, verifies no additional execution-attempt rows were created, and asserts a decision disagreement is reported without a cross-framework score or average. A second real-engine test drives a real `RunEngine` execution and then proves the application's invocation count and execution IDs are unchanged while both real adapters score those stored outputs. Added a deterministic Ragas judge with a deliberately different policy for the cross-framework diagnostic; it remains a real `InstructorBaseRagasLLM` response-model implementation.
- **Operational/documentation wiring:** Updated plugin discovery/startup bounds and CI paths, release-check plugin wiring, `docs/support.md`, `README.md`, `docs/engineering/platform-matrix.md`, ADR 0013, schemas, and the Prompt 14 ledgers/report. Existing concurrent Prompt 15 work was preserved and is not counted as Prompt 14 evidence.

## 4. Decisions or specification discrepancies recorded

- `docs/adr/0013-ragas-adapter-and-comparison-compatibility.md` records the Ragas-over-Promptfoo choice, exact API pin, recorded-output boundary, strict compatibility gates, legacy-plan fail-closed behavior, frozen-artifact fail-closed behavior, exploratory mode, grouped statistics, cached-repeat exclusion, and same-execution cross-framework diagnostic.
- Ragas 0.4.3 is affected by GHSA-95ww-475f-pr4f / CVE-2026-6587 in multi-modal URL/file processing. The adapter exposes/calls only validated text Faithfulness; the collection import may load module definitions, but no URL/file or `MultiModalFaithfulness` entry point is selected. This is a compensating worker control, not a claim that the dependency is vulnerability-free.
- `status=qualified` means identity compatibility; `claim_qualified=true` additionally requires a passing coverage gate and at least one complete pair. Coverage-failed and empty comparisons must not support a quality claim, and CLI exit code 1 is preserved for that case.
- The declared dependency identity freezes direct package/adapter versions and the declared worker interpreter/target for model-backed metrics; a future full transitive lockfile can strengthen it. Application target/revision changes remain comparable when the observation-extraction contract is unchanged. Strict identity also requires the canonical result-level identity; compact historical profiles remain exploratory.
- Prompt 14's local gates do not constitute the broader Phase 2 time-saved study, live-provider validation, cross-platform support, or a patched Ragas release. A `python_factory` judge's code drift behind an unchanged import string is also not treated as a package-version identity; production use should prefer a pinned adapter/package identity or remain exploratory.
