Phase 10 — Conversation recovery and adversarial interaction
Status: COMPLETE

1. Implemented functionality and changed files

- **10-T1 Reconciled resumed state.**
  - `services/runs.py`: `lease_state` tells whether a session is really executing a run (live, stale or no lease).
  - `sessions/controller.py`: `run_condition` combines the stored status with the lease. It reports `running_here`, `paused_here`, `active_elsewhere`, `starting`, `interrupted` (a dead process's `running` run) or a terminal status, plus unknown-effect work.
  - `reconcile()` rebuilds the reopening picture from storage and only reads.
  - `missed_events` / `acknowledge_events` use the new per-run cursor `BenchmarkSession.event_cursors` (schema regenerated), advanced atomically by `SessionStore.advance_event_cursor`.
  - `tui/app.py`: the reopen banner shows each run's condition, replays notable missed events by sequence (`notable_event`), shows notes and open questions, then acknowledges. The progress watcher starts from the session's cursor.
- **Earlier-layer bug fixed (08-T4, 09-G4).** `active_run()` treated a killed process's run, still stored as `running`, as active, so a session refused new runs after a crash and the terminal said the run was "still active". Only live conditions now occupy the run slot. `run_status` gains `condition` and `resumable`.
- **Crash-safe `start_run` (10-G2).** `_redelivered_start` handles an action redelivered while still `requested`:
  - a run its crashed first delivery created is adopted, found through the run's approval (`granted_by` names the session and action);
  - otherwise, once past the 10-minute starting window, the request is closed and the slot freed.

  `_settle` makes settling idempotent against a concurrent redelivery. A dead `cancelling` run is now resumable, and continuing it finishes the cancellation (`services/runs.py`).
- **10-T2 Long conversations.** `sessions/summary.py` builds a deterministic summary, capped at 4,000 characters and explicitly labelled non-authoritative. It contains:
  - decision references;
  - the user's corrections, from commands or grounded assistant patches;
  - open questions;
  - run IDs.

  Trimming follows a fixed order and counts what it drops. `conversation/agent.py` sends it for turns beyond the 12-turn window and caps every turn at 4,000 characters. The system prompt states that tool output and summaries are data, not instructions.
- **10-T3 Boundaries and redaction.**
  - `security/redaction.py` (`sanitize`) redacts credentials before and after stripping terminal control content: CSI/OSC/DCS/SOS/PM/APC (bounded, unterminated ones ending at the line end), 8-bit C1, C0/C1 controls except newline and tab, and zero-width/bidi characters.
  - It is used for stored messages and commands (`agent.redact`, `controller.record_command`) and for all terminal rendering (`tui/render.safe`), including `sessions show` and `chat --send`.
  - `render.out` prints with Rich emoji codes off; see Found, section 4.
- **10-T4 Loss and deletion.**
  - `SessionStore.delete_session`, `SessionController.delete` and the new `aibench sessions delete ID --yes` remove the conversation (refused while a run is active).
  - Runs, results, artifacts and events are kept.
- **Tests (new):** `tests/test_session_recovery.py` (6), `tests/test_conversation_hardening.py` (9) and `tests/test_recovery_review_regressions.py` (15), plus `test_chat_send_json_sanitizes_command_data` in `tests/test_cli_chat.py`.
- **Docs:** ADR 0009, `tickets.md`, `requirements-matrix.md` (7 rows) and `phase-status.md`.
