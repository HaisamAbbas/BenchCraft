Phase 17 — OpenAI evaluation bridges and one platform connector
Status: COMPLETE

1. Implemented functionality and changed files

- **17-T1: openai/evals (open-source) bridge.** New plugin `plugins/openai_evals_oss/` (`aibench-openai-evals-oss`).
  - **Pinning.** `evals==3.0.1.post1` is installed without its declared dependencies, plus `requirements-lock.txt`, the set the allowlisted modules import.
  - **Allowlist.** `Match`, `Includes`, `FuzzyMatch` and `JsonMatch` run unchanged (`upstream.py`); everything else is refused.
  - **Recorded replay** (`replay.py`, metrics `openai_evals_oss.<type>`): the eval's request must equal the recorded input exactly (type-tagged canonical form), once per sample. Otherwise the result is `unsupported_dynamic_request` or `unsupported_follow_up`.
  - **Live bridge** (`bridge.py` worker; core `src/aibench/services/delegated.py`; CLI `aibench openai-evals-oss run`):
    - The worker reports each sample's exact request, and each request becomes a case.
    - The harness invokes the application once per sample through its runner, and records a `delegated_suite` run with the plugin's identity.
    - The outputs are then replay-scored, and a disagreement between the live and replay verdicts is reported.
    - The bridge refuses an application that would not receive the whole input unchanged.
  - **Upstream quirks handled.** The import-time OpenAI client gets a placeholder key and a closed loopback URL. `blobfile` can't read Windows drive paths, so data files are passed as relative paths.
- **17-T2: hosted OpenAI Evals API bridge.** New plugin `plugins/openai_evals_api/` (`aibench-openai-evals-api`).
  - **Pinning and contract.** `openai==3.19.2`. `contract.py` builds a custom-schema eval and a `jsonl` data source of recorded items. Graders are `string_check`, `text_similarity` and `label_model`. `{{sample.*}}` templates and `completions`/`responses` data sources are refused.
  - **Worker** (`worker.py`): SDK retries off, redirects refused, environment proxies ignored, and failures classified.
  - **Core** (`src/aibench/services/remote_jobs.py`, migration 10 `remote_jobs`):
    - policy checks happen before any plugin code runs;
    - requests are stored, with a fingerprint, as a restricted artifact before sending;
    - the job is saved as `*_unknown` before every create;
    - ambiguous creates are reconciled by the job ID in remote metadata; resending needs `--resend`, and duplicate jobs need `--allow-duplicate`;
    - poll, cancel and paginated fetch follow;
    - results map one-to-one to the executions that were uploaded, and enter the run as a `remote-<job>` scoring pass.
  - **Other core pieces:**
    - `EvaluatorManifest.consumes` gains `remote_job`, which registry validation and plan analysis refuse;
    - `BindingScorer.record_outcome`;
    - CLI `aibench openai-evals-api submit|status|resume|cancel|fetch|jobs`.
- **17-T3: Langfuse connector** (the default choice, recorded as reversible). `src/aibench/connectors/langfuse.py`, CLI `aibench langfuse import-dataset|import-traces|export-scores|status`.
  - **Endpoints.** Langfuse v4 public API only, checked against the generated client of `langfuse==4.15.6`.
  - **Dataset import.** Items become cases that keep their Langfuse identity and version.
  - **Trace import.** Trace ID = correlation ID, using the OpenTelemetry usage rules.
  - **Score export.** Only `ok` results are exported, from the latest pass or `--scoring-id`, to the source host only. Each score is read back before and after creation. Conflicts are reported, never overwritten.
  - It never computes a metric.
- **17-T4: exposure.** `src/aibench/services/integrations.py` feeds `aibench integrations list`, chat `/integrations` and the assistant's `list_integrations` tool. For each integration it gives:
  - modes, including unsupported ones;
  - data destinations and credentials;
  - availability, with the exact reasons when unavailable;
  - live verification status.

  Planning catalog entries carry `consumes` and `network_destinations`, and `remote_job` metrics are ineligible. New policy field `allowed_egress_origins` (`security/policy.py`, `egress_denials`).
