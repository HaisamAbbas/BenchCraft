Phase 05 — DeepEval adapter
Status: COMPLETE (the optional live-provider smoke was not run: no credentials or budget were authorized)

1. Implemented functionality and changed files

- **05-T1 Pin and isolate.**
  - `deepeval==4.2.5` was inspected in the installed package: signatures of `FaithfulnessMetric`, `LLMTestCase` and `DeepEvalBaseLLM`; how the judge is called (`a_generate(prompt, schema=...)`); cost semantics (`evaluation_cost=None` for custom judges); and side effects (a `.deepeval/` directory in the working directory, `.env` loading, a legacy key file, default retries of 2).
  - The plugin package `plugins/deepeval/` (`aibench-deepeval`, exact pin, entry point `aibench.evaluators`) is installed into its own environment, `plugins/deepeval/.venv` (git-ignored).
  - The core has no DeepEval dependency and never imports it.
- **05-T2 Field semantics.** `plugins/deepeval/src/aibench_deepeval/faithfulness.py`:
  - `case.input` → `input`; recorded text output → `actual_output`; observed retrieval → `retrieval_context` (blank chunks dropped).
  - `reference.context` and `expected_output` are never passed.
  - Policies are documented in ADR 0004 and the README:
    - retrieval not observed → `missing:execution.retrieved_context`
    - retrieval empty (or only blank chunks) → `empty:execution.retrieved_context`
    - empty or non-text answer → `unscorable_output:*`
    - no claims extracted → `no_claims`

    All four are `not_applicable`; none produces a vacuous 1.0.
- **05-T3 Bounded execution.**
  - Generic worker execution for third-party evaluators: `src/aibench/registry/eval_worker.py` (a JSON-lines worker with fd 1 redirected to stderr) and `src/aibench/evaluators/worker_client.py`.
  - Each binding gets one worker, whose process tree is killed on timeout or cancellation. Its environment is an allow-list with a private working directory and HOME, plus only the explicitly configured secrets, which are redacted before truncation.
  - Other protections: a schema-version handshake, validation of usage records, and startup kept outside the per-case budget via `Evaluator.ensure_ready()` and `prepare_timeout_seconds`.
  - `EvaluatorRegistry.load_plugin_environment` (in `registry/__init__.py`), plus `discovery.environment_site_paths` and a private working directory for the manifest worker.
  - CLI options `--plugin-env`, `--plugin-secret` and `--plugin-path` (`src/aibench/cli/score.py`).
  - The adapter creates a new metric and a new judge per case, turns off DeepEval telemetry, `.env` loading, the legacy key file and its own retries, and declares `internal_retries=0` and `internal_concurrency=2`. The raw artifact keeps the score, reason, truths, claims, verdicts, and the upstream success flag and threshold. Unknown cost stays unknown.
  - Core additions (additive): `EvaluatorManifest.internal_concurrency` (≥1), `internal_retries` (≥0), `UsageReport.calls` may be `None`, and the `Evaluator.ensure_ready()` hook.
- **05-T4 Honest verification.**
  - `tests/fixtures/deepeval_judges/aibench_test_judges.py` holds real `DeepEvalBaseLLM` subclasses (a deterministic token judge, plus slow, failing and blocking variants).
  - `tests/test_deepeval_adapter.py` covers the real package, with an opt-in live smoke; `tests/test_worker_evaluator.py` covers the protocol.
  - A CI job, `deepeval-plugin`, runs these on Ubuntu and Windows.
  - No fake `deepeval` module exists anywhere.
- **Also changed:** `tests/test_dependency_boundaries.py`, `tests/test_plugin_discovery.py` (timing margin), `.gitignore`, `.github/workflows/ci.yml`, `plugins/deepeval/README.md`, ADR 0004, and the ledgers.
