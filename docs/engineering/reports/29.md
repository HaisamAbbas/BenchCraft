## 5. Product value and external capability review

### Verified implementation

This repository now has a bounded static inspector; evidence-backed profiles; policy-scoped dataset discovery; objective-to-metric opportunities that preserve missing evidence; a scripted conversational run/report/rescore loop; and a configured JSON HTTP runner. The clean-install and focused tests above verify those specific local contracts. They do not establish live-model quality, human usability, reduced setup time or adoption.

### Sourced framework and agent-workflow capabilities

Official documentation confirms adjacent frameworks already expose substantial evaluation and agent workflows. DeepEval documents 50+ metrics, black-box input/output evaluation, and agent trajectory/component metrics ([DeepEval metrics introduction](https://deepeval.com/docs/metrics-introduction)); its current page shows 4.2.6, while this repository's isolated adapter is pinned and tested at 4.2.5. Ragas documents RAG metrics and agent/tool metrics such as tool-call accuracy/F1 and agent-goal accuracy ([Ragas available metrics](https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/)). LangSmith documents offline/online evaluation, regression/backtesting, pairwise evaluation, and LLM/code/composite evaluators ([LangSmith evaluation types](https://docs.langchain.com/langsmith/evaluation-types)). OpenAI's Agents SDK documents tools, handoffs, guardrails, persistent sessions, tracing and human-in-the-loop workflows ([Agents SDK](https://openai.github.io/openai-agents-python/), [session workflows](https://openai.github.io/openai-agents-python/sessions/)).

These are vendor-maintained primary sources, checked 2026-09-25. They verify documented capabilities only; they do not prove relative quality or adoption. A conversational shell, persistent session or adapter list is not a unique claim.

### Proposed differentiation

A plausible product angle is a grounded path from an approved repository to evidence-backed evaluation choices, a policy-validated configured run, stored case evidence and offline rescore, while unavailable observations stay unavailable. This is a proposed positioning based on the local implementation, not a verified market advantage. The missing source-profile-to-chat journey must be closed before even the local end-to-end version is accepted.
